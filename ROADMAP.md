# Mentalix — Roadmap v1

Статус: предлагаемый порядок работ. Не является разрешением на продуктовые или визуальные изменения.

## Фактический статус на 29.07.2026

### Verified completed

- production-сборка восстановлена;
- `FORCE_EVENING_REVIEW=false`, вечерний сценарий зависит от `review_hour`;
- smoke-тест пяти вкладок и web auth пройден;
- Telegram fullscreen, safe areas и основной сценарий проверены на iPhone;
- ритуал, аскеза, вечерний анализ, Следопыт и Тренды проверены на одном
  тестовом аккаунте;
- выбор трёх AI-персон, отдельный диалог и ответ Следопыта работают.

### In progress

- системный UI-аудит;
- продуктовые события core loop;
- полировка длинных AI-диалогов и error/retry;
- семидневный тест на 5–10 пользователях.

### Planned

- автоматические тесты, lint и frontend error reporting;
- консолидация архитектуры после P0–P3;
- развитие Пути, аналитики и контента после подтверждения core loop.

### Requires product decision

- финальная палитра;
- архитектура публикации статей;
- роль курсов и тем недели;
- монетизация, entitlement и age/legal решение.

Следующий приоритет: системный UI-аудит без расширения набора функций, затем измеряемый пользовательский тест core loop.

## P0. Стабилизировать текущее состояние

Цель: получить честную baseline-сборку перед экспериментами.

- [x] отключить тестовый вечерний режим: `FORCE_EVENING_REVIEW=false`;
- [x] зафиксировать baseline build;
- [x] провести smoke-тест пяти вкладок;
- [x] проверить Telegram fullscreen/safe areas на реальном iPhone;
- [x] проверить web auth и повторный вход;
- [x] подтвердить основной core loop на одном тестовом аккаунте;
- сверить frontend API с приватным backend.

Критерий: известен результат каждого ключевого сценария и нет тестового режима в production.

## P1. Подтвердить ежедневный core loop

Цель: пользователь понимает следующий шаг и возвращается завтра.

```text
check-in → следующий шаг → практика → вечерний разбор → продолжение завтра
```

- проверить первое использование с пустыми ритуалами/аскезами;
- [x] проверить основной сценарий утра и вечера на одном тестовом аккаунте;
- проверить завершение всех типов практик;
- [x] проверить удержание и срыв аскезы;
- [x] проверить переход в AI и обратно;
- определить события продуктовой аналитики;
- измерить completion и next-day return.

Критерий: цикл проходит end-to-end, измеряется и понятен без объяснения автора.

## P2. Довести AI-сценарии

- три персоны и их различия;
- поле ввода с iPhone keyboard;
- длинный диалог;
- восстановление истории;
- новый journal entry;
- error/retry state;
- безопасные границы ответов.

Критерий: каждая персона проходит сценарий на реальном устройстве без потери текста и истории.

## P3. Наблюдаемость и защита от регрессий

- lint;
- минимальные тесты функций core loop;
- integration-тест API-клиента;
- e2e smoke для критического пути;
- централизованный frontend error reporting;
- чек-лист перед merge.

Критерий: критическая поломка ловится до production или диагностируется по событию, а не по скриншоту пользователя.

## P4. Консолидация архитектуры

Только после P0–P3:

- уменьшить обязанности `App.jsx`;
- формализовать navigation state;
- унифицировать loading/error/empty;
- вынести бизнес-вычисления из крупных экранов;
- определить судьбу legacy `habits`;
- мигрировать legacy design aliases отдельным PR при доказанной пользе.

Критерий: изменение одного сценария не требует несвязанных правок по всему приложению.

## P5. Путь, аналитика и контент

- определить главную метрику Пути;
- не показывать корреляции на недостаточной выборке;
- связать инсайт с конкретным действием;
- выбрать архитектуру статей;
- определить роль курсов и тем недели;
- подготовить хотя бы один законченный авторский трек.

## P6. Монетизация и публичный MVP

Только после подтверждённого core loop:

- решение Telegram Stars/web payment;
- entitlement-модель;
- age/legal решение;
- recovery сценарии оплаты;
- закрытый cohort;
- исправление blocker issues;
- публичный запуск.

## Не делать параллельно

- крупный редизайн и проверку core loop;
- архитектурную миграцию и новую продуктовую функцию;
- смену токенов и исправление mobile behavior;
- монетизацию до подтверждения ежедневной ценности.
