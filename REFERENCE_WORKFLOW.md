# Mentalix — Reference Workflow v1

Цель: использовать референсы как источник принципов, не копируя чужой продукт.

## 1. Вход

Для каждого референса зафиксировать:

- ссылка или скриншоты;
- конкретный экран и состояние;
- что именно нравится;
- какую проблему Mentalix он должен помочь решить;
- платформа и размер устройства.

Фразы «сделай как здесь» недостаточно.

## 2. Разбор референса

Анализировать отдельно:

- информационную иерархию;
- главный пользовательский шаг;
- композицию и плотность;
- типографическую иерархию;
- состояния и обратную связь;
- motion;
- accessibility;
- platform behavior.

Не переносить автоматически цвет, брендинг, иллюстрации, тексты и уникальные узнаваемые элементы.

## 3. Извлечение принципов

Формат:

```text
Нравится:
- один главный CTA;
- крупный заголовок;
- вторичная информация раскрывается позже.

Не переносим:
- палитру;
- бренд;
- конкретную иллюстрацию;
- тексты.

Принцип:
- на первом экране одна доминирующая задача;
- прогресс виден, но не конкурирует с действием.
```

## 4. Перевод в Mentalix

Каждый принцип проверить против:

- product core loop;
- фактической навигации;
- фактической типографики (`DESIGN_SYSTEM.md` §3);
- фактических CSS-токенов;
- шкалы радиусов;
- золотого акцента;
- safe areas Telegram;
- тона продукта.

Результат должен выглядеть как Mentalix, а не как перекрашенный референс.

## 5. Спецификация до кода

Подготовить:

- пользовательский сценарий;
- wireframe словами или изображением;
- состояния loading/empty/error/success;
- CTA и тексты;
- компоненты для переиспользования;
- затрагиваемые файлы;
- вопросы, требующие решения.

Если меняется продукт или визуальный язык, остановиться до согласования.

## 6. Реализация

- сначала минимальный вариант;
- без параллельного рефакторинга;
- с существующими токенами;
- с сохранением web/Telegram;
- с отдельной фиксацией любого вынужденного отступления.

## 7. Проверка

Сравнивать в три стороны:

1. референс — соблюдён ли извлечённый принцип;
2. Mentalix — сохранён ли бренд и core loop;
3. устройство — работает ли реальный мобильный сценарий.

Проверить минимум: 320 px, типичный iPhone, длинный текст, loading/error/empty, safe areas, keyboard при наличии input, reduced motion.
