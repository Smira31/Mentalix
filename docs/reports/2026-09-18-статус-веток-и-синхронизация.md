В frontend-репозитории остаются три вспомогательные ветки: `feat/issue-647-same-site-auth`, `fix/checkin-visual-polish` и `fix/production-demo-host`. Они не являются текущим Production и не входят в `main`. Их наличие не означает наличие незакоммиченных изменений в Production.

В backend-репозитории остаются ветки Dependabot с обновлениями зависимостей. Они также не входят в `main` и не влияют на текущий Production. Ветка исправления веб-авторизации удалена после merge PR #74.

## Коммиты и PR текущей задачи

Исправление авторизованного Production выполнено в backend PR [#74](https://github.com/Smira31/mentalix-bot/pull/74). PR был смержен в `main` с merge-коммитом `472d05d18f852221636726853171a31cfdc92247`.

Изменение добавило поле `id` в ответы `auth/session`, email login и Telegram login. Это устраняет ситуацию, при которой frontend обращался к user-scoped API без `user_id` и получал HTTP 422.

## Ограничение интерпретации

Обычный Production без параметра `demo=1` при отсутствии авторизации показывает экран входа. Production demo и Cloudflare demo-preview показывают демо-экран. Это ожидаемое различие состояния авторизации, а не расхождение исходного кода или собранных JS/CSS-файлов.
