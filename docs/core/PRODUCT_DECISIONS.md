# Решения Mentalix Core

Формат ADR-lite. Статус `предложено` означает, что решение подготовлено в draft PR и не считается принятым в `main` до merge.

## MXL-DEC-001 — Организовать методологию вокруг проблем пользователя

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** книжная навигация фрагментирует знания и начинает с источника, а не с задачи человека.
- **Решение:** книги являются источниками, а не основной навигацией знаний. Верхний уровень — проблемы пользователя.
- **Последствия:** идеи получают трассировку к проблеме, практике, проверке и рискам; каталог авторов остаётся библиографическим слоем.
- **Альтернативы:** сохранить структуру «книга → конспект → контент»; группировать знания по функциям приложения.
- **Связанные документы:** [`README.md`](README.md), [`KNOWLEDGE_GRAPH.md`](KNOWLEDGE_GRAPH.md).

## MXL-DEC-002 — Создать Mentalix Core как отдельный нормативный слой

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** существующая методология описывает правила и источники, но не имеет единого интеграционного слоя между проблемой и продуктом.
- **Решение:** Core связывает проблемы, законы, модели, методы, инструменты и продуктовые решения.
- **Последствия:** `docs/core/` становится точкой интеграции, а `docs/methodology/` сохраняет принципы и разборы источников.
- **Альтернативы:** расширять один файл Конституции; хранить связи только в контенте.
- **Связанные документы:** [`README.md`](README.md), [`CORE_PRINCIPLES.md`](CORE_PRINCIPLES.md).

## MXL-DEC-003 — Не переносить идеи из книг напрямую в продукт

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** буквальный перенос усиливает авторитет источника, скрывает риски и не подтверждает пользовательскую ценность.
- **Решение:** обязателен промежуточный путь через анализ, Core, практику и проверку.
- **Последствия:** продуктовая идея без трассировки остаётся гипотезой и не получает автоматического разрешения на внедрение.
- **Альтернативы:** редакторская адаптация напрямую из книги; публикация конспектов.
- **Связанные документы:** [`BOOK_METHODOLOGY.md`](BOOK_METHODOLOGY.md), [`../methodology/README.md`](../methodology/README.md).

## MXL-DEC-004 — Считать законы Core рабочими гипотезами

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** доступные книги и заметки обработаны с разной глубиной; научная и продуктовая проверка не завершена.
- **Решение:** до проверки исследованиями и пользовательскими тестами не использовать язык абсолютной истинности и статусы «принято» или «подтверждено».
- **Последствия:** каждый закон содержит границы, источники и вопросы для проверки.
- **Альтернативы:** называть положения принципами без статуса; принять их экспертным решением владельца.
- **Связанные документы:** [`MENTALIX_LAWS.md`](MENTALIX_LAWS.md).

## MXL-DEC-005 — Использовать AI как инструмент мышления

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** AI полезен для структурирования, но может ошибаться, соглашаться с ложными предпосылками и создавать убедительные выдумки.
- **Решение:** AI помогает различать факты и интерпретации, задавать вопросы и проектировать безопасные эксперименты, но не является источником окончательных решений.
- **Последствия:** значимые выводы требуют внешней проверки; диагнозы, давление и решения за пользователя запрещены.
- **Альтернативы:** AI как директивный наставник; AI только как поиск по контенту.
- **Связанные документы:** [`CORE_PRINCIPLES.md`](CORE_PRINCIPLES.md), [`MENTALIX_LAWS.md`](MENTALIX_LAWS.md).

## MXL-DEC-006 — Проверить архитектуру на вертикали «Не могу начать»

- **Дата:** 02.08.2026
- **Статус:** предложено
- **Контекст:** наличие карты и источников ещё не показывает, что проблемно-ориентированная архитектура приводит к безопасной и измеримой практике.
- **Решение:** объединить 15 проблем в пять кластеров, предварительно приоритизировать их и первой довести до малого теста проблему `MXL-PRB-002`.
- **Последствия:** до результата теста не разрабатывать отдельную функцию; рейтинг пересматривается после интервью и продуктовых данных.
- **Альтернативы:** сначала заполнить все 15 подробных карточек; начать с аудита существующих функций; выбрать проблему без критериев.
- **Связанные документы:** [`../problems/PROBLEMS.md`](../problems/PROBLEMS.md), [`../problems/ne-mogu-nachat.md`](../problems/ne-mogu-nachat.md).

## MXL-DEC-007 — Разрешить персональный пилот после интервью владельца

- **Дата:** 02.08.2026
- **Статус:** предложено владельцем
- **Контекст:** интервью `P01` выявило персональный сценарий: общее утреннее намерение вытесняется более заметной задачей, а ресурс меняется из-за сна и времени. Владелец решил проходить продуктовый цикл на собственном использовании, не ожидая выборку из 5–10 человек.
- **Решение:** одного интервью владельца достаточно для проектирования и разработки отдельного персонального пилота. Решение не отменяет границы безопасности и не является подтверждением эффективности для других пользователей.
- **Последствия:** фича маркируется как пилот; собираются только минимальные продуктовые события; выводы относятся к `P01`, пока не появятся другие данные. Массовые обещания и статус «проверено» запрещены.
- **Альтернативы:** ждать пять интервью; остановиться на документации; внедрить решение без измерения.
- **Связанные документы:** [`../research/ne-mogu-nachat-synthesis-template.md`](../research/ne-mogu-nachat-synthesis-template.md), [`../problems/ne-mogu-nachat.md`](../problems/ne-mogu-nachat.md).

## MXL-DEC-008 — Ограничить тестовый цикл двумя функциями

- **Дата:** 02.08.2026
- **Статус:** предложено владельцем
- **Контекст:** владелец хочет быстрее проходить персональный продуктовый цикл, не ожидая внешнюю выборку, но сохранить возможность понять результат каждого изменения.
- **Решение:** в один тестовый цикл включать не более двух связанных пользовательских функций с отдельным наблюдаемым результатом для каждой.
- **Последствия:** связанные функции можно проектировать и выпускать одним PR; крупные несвязанные изменения остаются отдельными циклами; критическое исправление не расходует лимит функции.
- **Альтернативы:** тестировать строго по одной функции; выпускать произвольный пакет изменений без разделения результатов.
- **Связанные документы:** [`../../AI_RULES.md`](../../AI_RULES.md), [`../engineering/EVENING_REVIEW_PILOT.md`](../engineering/EVENING_REVIEW_PILOT.md).
