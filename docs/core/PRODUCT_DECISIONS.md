# Решения Mentalix Core

Формат ADR-lite. Статус `предложено` означает, что решение подготовлено в draft PR и не считается принятым в `main` до merge.

## MXL-DEC-001 — Организовать методологию вокруг проблем пользователя

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** книжная навигация фрагментирует знания и начинает с источника, а не с задачи человека.
- **Решение:** книги являются источниками, а не основной навигацией знаний. Верхний уровень — проблемы пользователя.
- **Последствия:** идеи получают трассировку к проблеме, практике, проверке и рискам; каталог авторов остаётся библиографическим слоем.
- **Альтернативы:** сохранить структуру «книга → конспект → контент»; группировать знания по функциям приложения.
- **Связанные документы:** [`README.md`](README.md), [`KNOWLEDGE_GRAPH.md`](KNOWLEDGE_GRAPH.md).

## MXL-DEC-002 — Создать Mentalix Core как отдельный нормативный слой

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** существующая методология описывает правила и источники, но не имеет единого интеграционного слоя между проблемой и продуктом.
- **Решение:** Core связывает проблемы, законы, модели, методы, инструменты и продуктовые решения.
- **Последствия:** `docs/core/` становится точкой интеграции, а `docs/methodology/` сохраняет принципы и разборы источников.
- **Альтернативы:** расширять один файл Конституции; хранить связи только в контенте.
- **Связанные документы:** [`README.md`](README.md), [`CORE_PRINCIPLES.md`](CORE_PRINCIPLES.md).

## MXL-DEC-003 — Не переносить идеи из книг напрямую в продукт

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** буквальный перенос усиливает авторитет источника, скрывает риски и не подтверждает пользовательскую ценность.
- **Решение:** обязателен промежуточный путь через анализ, Core, практику и проверку.
- **Последствия:** продуктовая идея без трассировки остаётся гипотезой и не получает автоматического разрешения на внедрение.
- **Альтернативы:** редакторская адаптация напрямую из книги; публикация конспектов.
- **Связанные документы:** [`BOOK_METHODOLOGY.md`](BOOK_METHODOLOGY.md), [`../methodology/README.md`](../methodology/README.md).

## MXL-DEC-004 — Считать законы Core рабочими гипотезами

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** доступные книги и заметки обработаны с разной глубиной; научная и продуктовая проверка не завершена.
- **Решение:** до проверки исследованиями и пользовательскими тестами не использовать язык абсолютной истинности и статусы «принято» или «подтверждено».

## MXL-DEC-005 — Использовать AI как инструмент мышления

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** AI полезен для структурирования, но может ошибаться, соглашаться с ложными предпосылками и создавать убедительные выдумки.
- **Решение:** AI помогает различать факты и интерпретации, задавать вопросы и проектировать безопасные эксперименты, но не является источником окончательных решений.
- **Последствия:** значимые выводы требуют внешней проверки; диагнозы, давление и решения за пользователя запрещены.
- **Альтернативы:** AI как директивный наставник; AI только как поиск по контенту.
- **Связанные документы:** [`CORE_PRINCIPLES.md`](CORE_PRINCIPLES.md), [`MENTALIX_LAWS.md`](MENTALIX_LAWS.md).

## MXL-DEC-006 — Проверить архитектуру на вертикали «Не могу начать»

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** наличие карты и источников ещё не показывает, что проблемно-ориентированная архитектура приводит к безопасной и измеримой практике.

- **Последствия:** до результата теста не разрабатывать отдельную функцию; рейтинг пересматривается после интервью и продуктовых данных.
- **Альтернативы:** сначала заполнить все 15 подробных карточек; начать с аудита существующих функций; выбрать проблему без критериев.
- **Связанные документы:** [`../problems/PROBLEMS.md`](../problems/PROBLEMS.md), [`../problems/ne-mogu-nachat.md`](../problems/ne-mogu-nachat.md).
- **Обновление 09.08.2026 — разработка под `MXL-PRB-002` разрешена до статуса «проверено»:**
  - Владелец осознанно разрешает разработку функционала по вертикали `MXL-PRB-002` («Не могу начать») до получения формального статуса «проверено».
  - Критерий из пяти живых проблемных интервью (`PROBLEMS.md`) не закрыт: одно живое интервью владельца (`MXL-RSCH-001`) + четыре находки анализа открытых источников (`../problems/ne-mogu-nachat.md`, раздел «Материал `MXL-RSCH-002`»), допустимые только как более слабая альтернатива по `MXL-DEC-007`.
  - **Риск — повышенный:** разрабатываемая функция может не соответствовать реальной проблеме аудитории, а не только личному опыту владельца, поскольку доказательная база собрана не по правилу «минимум пять интервью».
  - Исключение ограничено только `MXL-PRB-002` и **не отменяет** правило «до результата теста не разрабатывать отдельную функцию» для остальных 14 проблем карты.

## MXL-DEC-007 — Разрешить персональный пилот после интервью владельца

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** интервью `P01` выявило персональный сценарий: общее утреннее намерение вытесняется более заметной задачей, а ресурс меняется из-за сна и времени. Владелец решил проходить продуктовый цикл на собственном использовании, не ожидая выборку из 5–10 человек.
- **Решение:** одного интервью владельца достаточно для проектирования и разработки отдельного персонального пилота. Решение не отменяет границы безопасности и не является подтверждением эффективности для других пользователей.
- **Последствия:** фича маркируется как пилот; собираются только минимальные продуктовые события; выводы относятся к `P01`, пока не появятся другие данные. Массовые обещания и статус «проверено» запрещены.
- **Альтернативы:** ждать пять интервью; остановиться на документации; внедрить решение без измерения.
- **Связанные документы:** [`../research/ne-mogu-nachat-synthesis-template.md`](../research/ne-mogu-nachat-synthesis-template.md), [`../problems/ne-mogu-nachat.md`](../problems/ne-mogu-nachat.md).

## MXL-DEC-008 — Ограничить тестовый цикл двумя функциями

- **Дата:** 02.08.2026
- **Статус:** принято
- **Контекст:** владелец хочет быстрее проходить персональный продуктовый цикл, не ожидая внешнюю выборку, но сохранить возможность понять результат каждого изменения.
- **Решение:** в один тестовый цикл включать не более двух связанных пользовательских функций с отдельным наблюдаемым результатом для каждой.
- **Последствия:** связанные функции можно проектировать и выпускать одним PR; крупные несвязанные изменения остаются отдельными циклами; критическое исправление не расходует лимит функции.
- **Альтернативы:** тестировать строго по одной функции; выпускать произвольный пакет изменений без разделения результатов.
- **Связанные документы:** [`../../AI_RULES.md`](../../AI_RULES.md), [`../engineering/EVENING_REVIEW_PILOT.md`](../engineering/EVENING_REVIEW_PILOT.md).

## MXL-DEC-009 — Направление UI Lab: геометрическая база + органический переход

- **Дата:** 10.08.2026
- **Статус:** предложено владельцем
- **Контекст:** UI Lab (`src/components/ui-lab/UiExperiments.jsx`, формула `SemanticGlyph.jsx`) накопил ~24 экспериментальных варианта. Требовалось зафиксировать направление, а не перебирать варианты бесконечно. Разбор кода шести референсов (варианты `05`, `09`, `12`, `14`, `16`, `18`) показал, что деление «геометрия для статики / органика для движения» неточно: во всех вариантах геометрическая крестовина-гид присутствует как неподвижная подложка, а органическая форма анимируется поверх неё именно в момент перехода между состояниями.
- **Решение:** геометрическая крестовина-гид — неподвижная база во всех карточках; органическая форма (лепестки/линзы/волна и т. п.) анимируется поверх неё при переходах между состояниями, а не заменяет геометрию в статике. Базовые референсы направления: вариант `05` (геометрия/checkin — орбиты и стрелка), `09` (огранка/линзы), `12` (вложенные линзы), `14` (волна), `16` (створки-портал), `18` (зеркала-резонанс).
- **Последствия:** правило зафиксировано в [`MENTALIX_SEMANTIC_MOTION.md`](../../MENTALIX_SEMANTIC_MOTION.md) §4 и §4.1 — переход между состояниями `420–520ms` на `cubic-bezier(0.77, 0, 0.175, 1)` (раскрытие/появление — `cubic-bezier(0.23, 1, 0.32, 1)`), допустимые свойства перехода — `transform`, `opacity`, `stroke`. Новые карточки `SemanticGlyph` обязаны сохранять гид-подложку и не заменять геометрию органикой в состоянии покоя.
- **Альтернативы:** единый геометрический язык для всех состояний; единый органический язык для всех состояний; сохранить россыпь из ~24 несистематизированных вариантов без общего правила.
- **Открытые вопросы перед переносом в прод:** читаемость на вьюпорте 320×568; стоимость переноса органических вариантов из UI Lab в прод-компоненты (`MXL-UI-LAB-001`).
- **Связанные документы:** [`../../MENTALIX_SEMANTIC_MOTION.md`](../../MENTALIX_SEMANTIC_MOTION.md), `src/components/SemanticGlyph.jsx`, `src/components/SemanticGlyph.css`, `src/components/ui-lab/UiExperiments.jsx`, `src/components/ui-lab/UiExperiments.css`.
- **Обновление 10.08.2026:** владелец решил, что правило §4.1 распространяется не только на `SemanticGlyph`, но и на `CardSystemGlyph` — оценка стоимости переноса (см. `TASKS.md`, `MXL-UI-LAB-001`) выявила, что оба компонента независимо дублируют одну и ту же архитектуру («гид-крестовина + kind-based SVG») и используются параллельно на одних и тех же production-экранах (`Ascezas`, `Breathing`, `Focus`, `BrainTrainer`, `Practices`, `Today`), что создаёт два конкурирующих источника истины вместо одного. Решение: `SemanticGlyph` и `CardSystemGlyph` объединяются в единый реестр глифов; оба подчиняются §4.1 (гид-крестовина — неподвижная база, органика анимируется поверх неё только при переходах между состояниями). Перенос разбит на три цикла и заведён как отдельная задача `MXL-GLYPH-UNIFY-001` (`TASKS.md`) — до завершения Цикла 1 (картирование потребителей и план объединения) код не менять.

## MXL-DEC-010 — Тёплый тёмный фон вместо абсолютного чёрного

- **Дата:** 14.08.2026
- **Статус:** принято
- **Контекст:** текущий `--c-bg` в `DESIGN_SYSTEM.md` §2 — абсолютный холодный чёрный `#000000`. Mentalix — wellness-приложение, которым пользуются вечером в уязвимые моменты; резкий/холодный чёрный не соответствует ощущению спокойствия, которое приложение должно давать.
- **Решение:** перейти с абсолютного чёрного `#000000` на тёплый тёмный фон `#050403` (rgb 5 4 3) — минимальный сдвиг из трёх предложенных вариантов, безопасен для существующей иерархии слоёв: остаётся темнее текущей карточки `--c-card: #090909`, поэтому `--c-card`/`--c-card2`/`--c-border` пересчитывать не требуется.
- **Последствия:** hex выбран, но токен `--c-bg` в `src/index.css`/`DESIGN_SYSTEM.md` ещё не изменён в production — перед внедрением требуется визуальная проверка владельцем на реальном устройстве через временный dev/Preview-only флаг `?bg_preview=1` (см. `TASKS.md` → `MXL-021`). В `main` без отдельного подтверждения после живого просмотра не мержить.
- **Альтернативы:** оставить абсолютный чёрный (статус-кво); `#0A0806` — более заметный тёплый сдвиг, потребовал бы поднять `--c-card`/`--c-card2`; `#120F0B` — выраженный тёплый фон, потребовал бы пересчёта всего тёмного стека токенов.
- **Связанные документы:** [`../../DESIGN_SYSTEM.md`](../../DESIGN_SYSTEM.md) §2, `TASKS.md` → `MXL-021`.

## MXL-DEC-011 — Backend API для публикации статей вместо git-commit

- **Дата:** 14.08.2026
- **Статус:** принято
- **Контекст:** `MXL-022` в `TASKS.md` фиксировал развилку архитектуры публикации статей — backend API или commit в репозиторий. Владелец планирует публиковать статьи часто и самостоятельно, без участия разработчика на каждую публикацию.
- **Решение:** публикация статей — через backend API (админ-эндпоинт создания статьи), не через git-commit в репозиторий.
- **Последствия:** реализация не входит в это решение и требует отдельного цикла: админ-эндпоинт создания статьи в `mentalix-bot` backend, форма на фронте, доступ ограничен только владельцем. Задача `MXL-022` разблокирована для проектирования/реализации.
- **Альтернативы:** публикация commit’ом в репозиторий — отклонено: требует участия разработчика на каждую статью, не масштабируется под частую самостоятельную публикацию.
- **Связанные документы:** `TASKS.md` → `MXL-022`.

## MXL-DEC-012 — Ежедневное повторение по умолчанию для напоминаний

- **Дата:** 14.08.2026
- **Статус:** принято
- **Контекст:** `MXL-REMINDERS-002` в `TASKS.md` был заблокирован до выбора владельцем режима повторения по умолчанию (ежедневно или только в выбранные дни).
- **Решение:** по умолчанию напоминание повторяется ежедневно, как в стандартном будильнике телефона, с возможностью пользователю изменить дни или выключить напоминание.
- **Последствия:** блокер снят для дальнейшего проектирования UX. Реализация остаётся открытой — перед разработкой требуется проверить фактический API-контракт приватного backend/bot, см. `TASKS.md` → `MXL-REMINDERS-002`. Это решение не меняет код.
- **Альтернативы:** повторение только в выбранные дни по умолчанию — отклонено как менее очевидное поведение для пользователя, привыкшего к модели стандартного будильника.

## MXL-DEC-013 — Первый авторский трек по MXL-PRB-002: карточка «Первый шаг» в Практиках

- **Дата:** 15.08.2026
- **Статус:** принято
- **Контекст:** `MXL-DEC-006`/`MXL-DEC-007` разрешили разработку функционала по вертикали `MXL-PRB-002` («Не могу начать») до статуса «проверено», на основании одного живого интервью (`MXL-RSCH-001`) и находок анализа открытых источников (`MXL-RSCH-002`, `ne-mogu-nachat.md`, 9 находок на 09.08 и 15.08.2026 — вторичная, осознанно более слабая доказательность). - **Решение:** первый авторский трек по `MXL-PRB-002` — карточка «Первый шаг» внутри уже существующей вкладки «Практики» (`Practices.jsx`), рядом с остальными практиками, по тому же UI-паттерну открытия. Разовая практика без серии/стрика (осознанно — серия/сравнение противоречили бы собственному правилу практики «не использует серию, стыд или сравнение для давления», `ne-mogu-nachat.md`). Шесть шагов внутри многошагового флоу (переиспользует паттерн `TodayFocusFlow.jsx`, не изобретает новый): `task` (назвать дело) → `state` (что мешает, 5 нейтральных вариантов без клинических терминов, включая мягкую ветку «Устал(а)» — выход к отдыху вместо давления) → `plan` (шаг на 5 минут) → `run` (таймер) → `outcome` (начато/не начато/остановлено по безопасности) → `reflect` (субъективный самоотчёт «стало ли легче начать» — прямой вопрос, не поведенческое событие). Метрика успеха — только субъективная: локальный лог самоотчёта по датам (по образцу `todayFocus.js`), без backend-событий и без сохранения текста задачи за пределы сессии.
