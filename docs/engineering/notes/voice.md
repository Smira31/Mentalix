# Голос: этап 0 — запись микрофона в Telegram

Рабочие заметки «грабли» по скрытому экрану «Лаборатория: голос»
(`src/screens/VoiceLab.jsx`). Это проверка возможности, не пользовательская
функция: звук никуда не отправляется и не сохраняется.

## Как открыть экран

Скрытых экранов в приложении не было: `?ui_lab=…` монтируется в `src/main.jsx`
вместо `App` и разрешён только на localhost и превью-хостах (`src/lib/uiLabAccess.js`),
а в Telegram Mini App он недоступен; `Воля к оплате` — обычная видимая строка
профиля. Поэтому вход сделан по правилу из задачи: **7 быстрых нажатий по номеру
версии** внизу профиля (`profile-version`, `Settings.jsx`). В меню и вкладках
экрана нет, ссылок на него нет.

- Счётчик нажатий живёт в `Settings.jsx` (`versionTapsRef`), пауза между
  нажатиями больше 1,5 с сбрасывает счёт — «быстрые» нажатия не набираются
  случайно при обычном скролле.
- Нажатие по `<p>` не имеет роли кнопки: это намеренно скрытый жест, а не
  элемент управления. Скринридеры о нём не узнают.

## Запись

- Формат: `audio/mp4` → `audio/webm;codecs=opus` → `audio/ogg;codecs=opus` →
  формат браузера по умолчанию. iOS (все браузеры = WebKit) отдаёт только
  `audio/mp4`; Chromium (Android, Desktop) — `audio/webm;codecs=opus`;
  `audio/ogg;codecs=opus` в Safari не поддерживается.
- Если браузер принял `isTypeSupported`, но конструктор `MediaRecorder`
  выбросил исключение, экран один раз пробует формат по умолчанию — иначе на
  нестандартном webview проверка молча упиралась бы в отказ.
- Лимит 10 с держится таймером от `Date.now()`, а не суммой тиков: Telegram
  глушит таймеры в фоне.
- Треки останавливаются в `onstop`, в `onerror`, при исключении старта и при
  размонтировании экрана. Иначе индикатор микрофона в iOS остаётся горящим.
- Аудио живёт только в `Blob` + `URL.createObjectURL`; адрес отзывается при
  новой записи и при выходе с экрана. Ни localStorage, ни IndexedDB, ни сети.

## Отчёт

`Скопировать отчёт` собирает текст из `Telegram.WebApp.platform/version`,
`navigator.userAgent`, наличия `getUserMedia`/`MediaRecorder`, результата
`isTypeSupported` по трём форматам, выбранного формата, длительности, размера и
текста ошибки. Имени, id пользователя и `initData` в отчёте нет — специально,
чтобы его можно было переслать без персональных данных.

- `navigator.clipboard.writeText` в webview Telegram может быть запрещён без
  жеста; на этот случай есть запасной путь через `textarea` + `execCommand`.
- В обычном браузере без Telegram `platform`/`version` пустые, в отчёте
  печатается «не Telegram» — это ожидаемо и не ошибка.

## Проверка

- `npm run ux:voice-lab` (`playwright.voice-lab.config.mjs`, Chromium, свой
  dev-сервер на 4185): скрытый вход, отказ без `MediaRecorder`, отказ без
  `getUserMedia`. Кадры — `qa-evidence/voice-lab/`.
- В свежем web-контейнере перед первым прогоном:
  `npx playwright install --with-deps chromium`.
- Реальная запись в CI не проверяется: микрофона нет. iPhone / Android /
  Telegram Desktop — ручной gate владельца, в отчёте это NOT RUN, не PASS.
- Признак успеха на телефоне: после «Стоп» появляется `<audio>`, в отчёте
  выбран формат (`audio/mp4` на iOS) и размер больше нуля; после выхода с
  экрана индикатор микрофона в iOS гаснет.
