# UX/UI-аудит вкладки «Сегодня»

## 0. Рамка аудита

Цель — собрать единый продуктовый и визуальный путь по фактической реализации вкладки «Сегодня», сопоставить нормативные и исторические документы с кодом, зафиксировать конфликты и гэпы. Этот файл является **исследовательским отчётом**, а не планом исправлений: код, тексты и продуктовая логика в рамках аудита не меняются.

Проверяемый checkout на момент старта аудита: ветка `main`, SHA `ca1d21e84bd1ad0e071b2173604298a924d950dd`. Отчёт ведётся в ветке `audit/today-tab-2026-09-19`.

### Иерархия источников

При расхождении применяю порядок из `AGENTS.md`, `docs/DOCUMENTATION_GUIDE.md` и `docs/AGENT_ONBOARDING.md`: явная задача владельца → фактический код текущего checkout → актуальный GitHub/release evidence → профильный нормативный документ → исторические документы. ## 1. Предварительные находки и ограничения

### 1.1. Production URL в запросе не совпадает с текущей канонической картой окружений

- `PROJECT_STATE.md` и `docs/DOCUMENTATION_GUIDE.md` определяют **Production** как `main → Firebase Hosting Live → https://mentalix-production.web.app`.
- Те же документы определяют Vercel как отключённый старый fallback: новые проверки через Vercel не использовать.
- В пользовательском задании указан `mentalix.vercel.app` как «прод-версия».

**Статус:** конфликт окружений, требующий явной маркировки в evidence. До уточнения отчёт должен разделять проверку запрошенного URL и проверку канонической Production; недоступность/устарелость Vercel нельзя трактовать как дефект Today.

### 1.2. SHA в `PROJECT_STATE.md` не совпадает с фактическим checkout

- `PROJECT_STATE.md` §2 фиксирует текущий `main` как `048d4736...` после PR #628.
- Клонирование репозитория и `git rev-parse HEAD` дают `ca1d21e84bd1ad0e071b2173604298a924d950dd`.
- Открытых PR на момент старта аудита: `0`.

**Статус:** release-provenance discrepancy. Все выводы аудита ниже должны ссылаться на фактический SHA checkout; состояние документа не следует считать доказательством того, что этот SHA опубликован.

### 1.3. Фактическое дерево Today уже шире одной карточки

По импортам `src/screens/Today.jsx` вкладка напрямую включает или открывает:

- неделю (`WeekStrip`) и hero-карточку с состояниями check-in/вечернего разбора, empty, next action, all done, day closed;
- `CheckIn.jsx` как fullscreen flow;
- `Path.jsx`, `History.jsx`, `YearPath.jsx` как вложенные поверхности «Пути»/истории;
- `ThemeScreen.jsx` и цитату через `QuoteView.jsx`;
- `SeriesBadges.jsx` и серию;
- `StarterSetPicker` в empty-состоянии;
- дневную ленту/карточки, цитату дня, тему недели и social-proof pulse в основной разметке;
- UI Lab/demo-only ветки (`TodayMotionExperiment`, `isPreviewDemoMode`).

Полный inventory и статусы по каждому узлу будут заполнены после чтения оставшихся участков `Today.jsx`, связанных CSS и точечных продуктовых формулировок.

## 4. Ограничения доказательств

- Backend находится в приватном `Smira31/mentalix-bot`; API-контракт не выводится сверх frontend-кода и доступных фикстур.
- Без авторизованного аккаунта и стабильных серверных данных нельзя честно объявить data-dependent состояния (прошедший check-in, вечерний review, заполненная лента) подтверждёнными на live URL.
- UI Lab и demo fixtures не являются Production evidence; они будут помечены отдельно.

_Черновик создан сразу после первого содержательного чтения источников; дальнейшие разделы будут добавляться отдельными коммитами._

- **Не найдено отдельной полноценной Today-ленты практик:** главный экран показывает hero + progress/summary/theme/quote, а список самих практик открывается переходом в Practices через `onOpenPractice`; это соответствует принципу «не превращать Today в каталог», но должно быть явно отражено как product/code boundary.

## 10. Финальное решение по полноте evidence

Для production URL пользовательский запрос на «все состояния» выполнить полностью не удалось без выдумывания данных: оба live-окружения остались на splash и не предоставили authenticated Today. Поэтому отчёт разделяет:

1. **live evidence:** splash screenshots Vercel и Firebase;
2. **локальное visual evidence:** fixture Today/check-in в четырёх mobile viewport, UX smoke 11/11;
3. **статический evidence:** state machine и document/code matrix выше;
4. **не подтверждено:** вечер, заполненный день, next action и day closed в живой версии.

Это ограничение является частью результата аудита, а не скрытым `PASS` для незаснятых состояний.
