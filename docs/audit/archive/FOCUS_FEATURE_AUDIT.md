## Где находится Focus

Основной экран — `src/screens/Focus.jsx`. Он импортируется в `src/screens/Practices.jsx` (строка 19) и открывается условием `if (sub === 'focus')` (строки 276–289). В этом состоянии отрисовывается `<Focus user={user} />` с обычной кнопкой возврата. Это действующий production-маршрут, а не UI Lab-only прототип.

В `src/lib/practiceCatalogRegistry.js` есть полноценная запись каталога:

- `key: PRACTICE_KEYS.focus`;
- `title: 'Фокус'`;
- `subtitle: 'таймер глубокой работы'`;
- `section: 'Живая линза'`;
- `kind: 'focus'`;
- `sub: 'focus'`.

Там же коллекция `living-lens` включает четыре ключа: `meditation`, `breathing`, `focus` и `brain`. В `src/components/PracticeCatalogV2.jsx` коллекции показываются на стартовом экране, а после открытия коллекции `living-lens` её `practiceKeys` преобразуются в карточки. Для карточки Focus `soon` вычисляется из `isPracticeAvailable('focus')`; при текущем `main` это значение `false`, поэтому карточка рабочая и кликабельная.

## Почему владелец мог не найти Focus

Стартовый экран `PracticeCatalogV2` не показывает все практики сразу. Он показывает журнал, rail «Новое и рекомендованное», тему недели и сетку коллекций. Для rail в `PracticeRail` вручную создана отдельная карточка:

```js
{
  key: 'focus-preview',
  title: 'Фокус',
  category: 'Концентрация',
  status: 'СКОРО',
  kind: 'focus',
  active: false,
}
```

Она не ссылается на registry-запись `PRACTICE_KEYS.focus`, не имеет `sub` и отключается через `disabled={!card.active}`. Поэтому визуально на первом экране каталога пользователь видит именно «Фокус · Скоро» и не может открыть его. Рабочая Focus доступна только после последовательности: вкладка «Практики» → коллекция «Живая линза» → карточка «Фокус».

На экране «Сегодня» нет прямого запуска `Focus` или `onOpenPractice('focus')`. В `Today.jsx` есть `StarterSetPicker`, где слово «Фокус» является одним из контекстов выбора стартового ритуала; этот контекст создаёт ритуал «Один следующий шаг», а не запускает `src/screens/Focus.jsx`. Это отдельная функция и не является entry point для Focus-таймера. Также `TodayFocusCard.jsx` и `TodayFocusFlow.jsx` не подключают production-экран Focus в текущем `Today.jsx`.

## Гейтинг и переключатели

Единственный production-механизм доступности практик находится в `src/config/practiceAvailability.js`:

```js
export function isPracticeAvailable(practiceKey) {
  return AVAILABLE_PRACTICES.includes(practiceKey)
}
```

Ключ `PRACTICE_KEYS.focus` входит в `AVAILABLE_PRACTICES`. В `Practices.jsx` этот же метод используется для защиты входа в flow и в callback `onOpenPractice`: недоступная практика не открывается, но для текущего Focus условие проходит.

Проверка кода не обнаружила отдельного `VITE_*`-флага Focus, URL-параметра, query-переключателя или A/B-ветки, влияющих на `focus`. Единственный URL/feature-механизм рядом с практиками — UI Lab (`ui_lab`) и не относится к production-каталогу.

## Решение, оставшееся владельцу

Диагностика не включает и не выключает функцию и не меняет код. С технической точки зрения Focus сейчас **включён**, но плохо обнаруживается: рабочий вход спрятан на втором уровне каталога, тогда как первый уровень показывает одноимённое «Скоро».

С учётом того, что владелец ранее выражал недовольство текущей реализацией Focus, безопасная рекомендация — **не продвигать рабочую карточку на первый уровень и оставить пользовательский preview в статусе «Скоро» до пересмотра дизайна**. Если нужно полностью закрыть текущий Focus до переделки, это следует сделать отдельным явно согласованным продуктовым изменением: удалить `focus` из `AVAILABLE_PRACTICES` и сохранить flow-код для будущего возвращения. В рамках этого аудита такие изменения намеренно не выполнялись.

## Ограничения проверки

Проверены текущие исходники `main`, git history, `git blame` для availability, registry и preview-карточки, а также production-маршрутизация. Backend для этого вывода не нужен: наличие и доступность Focus определяются frontend registry и локальным allowlist. Ручная проверка на устройстве владельца не выполнялась; она потребуется отдельно, если после выбора продуктового решения нужно будет проверить обнаруживаемость или переделанный UI.
