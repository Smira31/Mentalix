## Правила следующего действия

Не закрывать и не удалять больше одного PR за раз. Перед каждым действием повторно получить свежий `origin/main`, проверить diff, mergeability, checks и ссылки на backlog. Для закрытия сохранить номер PR и причину в `CHANGES.md` или handoff. Для актуализации создавать новую feature-ветку от свежего main, не rebase старую ветку без явного решения.

## Handoff

| Поле | Состояние |
|---|---|
| Что изменилось | Подготовлен read-only triage открытых PR и coordination protocol |
| Где | `docs/handoffs/2026-08-27-pr-triage.md`, `docs/COORDINATION_PROTOCOL.md` |
| Что проверено | Состояние PR, checks, mergeability, изменяемые файлы и зависимости |
| Что не проверено | Полный line-by-line diff всех PR и фактическая каноничность каждого исторического документа |
| Следующий decision gate | Owner выбирает действие для одного PR; рекомендованный первый review — #241 |
| Риски | Старые branches конфликтуют с main; параллельные диалоги могут повторно изменить canonical docs |
| Rollback | Документационный PR откатывается отдельным revert; PR triage сам по себе не выполняет destructive actions |
