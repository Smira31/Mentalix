# Mentalix — передача контекста (обновлено 25.09.2026, вечер)

Главный файл для нового ассистента и любого агента. Прочитай целиком перед работой.
Рядом: docs/STATUS.md — доска задач (что в работе / сделано / очередь). AGENTS.md — правила агентов и стандарт промпта.

## 1. Роли
- Владелец (Smira31) — не программист. Решает, мержит PR, проверяет на iPhone. Общение по-русски, просто, коротко. Любит копировать-вставлять готовые промпты и минимум ручных действий.
- Ассистент (Claude): разбирает референсы (Stoic), пишет промпты агентам одним копируемым блоком, коротко проверяет итог (ветка, тесты, конфликты), ведёт этот файл и STATUS.md. PR глубоко не разбирает. Нет решения — один короткий вопрос.
- Агенты-разработчики: Base44 (основной), Codex, Manus. Одна задача = одна ветка = один PR.

## 2. Проект
- Фронт: Telegram Mini App, React/Vite, github.com/Smira31/Mentalix. Прод: mentalix-production.web.app (Firebase Hosting, деплой после мержа в main).
- Бэкенд и бот: приватный Smira31/mentalix-bot (FastAPI + SQLAlchemy, PostgreSQL в Neon, без Alembic — смена схемы только ручным SQL в Neon). Деплой Render. Проверка: https://mentalix-bot.onrender.com/api/health → {"status":"ok"}.
- Цель: повторить геометрию и поведение Stoic (отступы, размеры, жесты), тексты свои, по-русски.

## 3. Как проверять (без Telegram)
- Каждый PR получает ссылку-превью (workflow pr-preview.yml, бот Firebase пишет её в комментарий PR, живёт 7 дней). Открывать на iPhone в Safari с ?demo=1. Состояния «Сегодня»: &today_state=morningPrimary | eveningPrimary | bothDone | night | ...
- Постоянная ссылка (всегда свежий main, демо-данные): https://mentalix-production.web.app/?demo=1 — у владельца на экране «Домой».
- На реальном телефоне демо выглядит как в Telegram (без панели «Demo viewport», без фальшивой шапки); на ПК — с переключателем 393/440.
- Telegram — только изредка: реальные данные, клавиатура, нативная «Назад».
- Робот-обход (в CI, informational): скриншоты всех экранов 393/440 + summary.md с проблемами — artifact в каждом PR.
- Демо-панель: ?demo=1&panel=1 — машина времени, готовые аккаунты, сеть, сброс, наложение референса Stoic.
- Отладка прокрутки: ?debug=scroll (только демо).
- Проверять iOS-поведение в Playwright WebKit (devices['iPhone 15 Pro']); Chromium не доказательство для iPhone. На iOS все браузеры и Telegram = WebKit; на Android — Chromium.

## 5. Решения владельца (не пересматривать без него)
«Сегодня» и карточки дня
- Две карточки: утренний чек-ин и разбор дня. Утро доступно весь день до 04:59, пока не пройдено (как Stoic). Разбор закрыт до времени разбора (по умолч. 19:00).
- Как у Stoic: непройденная карточка — тёмно-серая заливка без обводки, без картинки, подпись в 2 строки, заголовок с жирным словом, кнопка «Начать» (главная — светлая залитая, вторая — контурная). Пройденная — фон экрана, тонкая обводка, приглушённый текст, персонаж владельца стоит на тонкой линии.
- Картинки персонажа (красная рогатая маска, чёрное тело): утро — голова вправо, активный взгляд; вечер — закрытые «отдохнувшие» глаза. Никаких птиц Stoic и чужих рисунков.
- Ночь 00:00–04:59: тексты про «вчера». Тексты: «Как ты сегодня?», «Закрой этот день.», «Утро отмечено.», «День закрыт.», «Вернись к началу вчера.», «Подведи итог вчера.».
- Огонёк серии: всегда виден; при 0 — контур с залитым маленьким огоньком внутри, без цифры; при ≥1 — залит, внутренний огонёк «вырезан».
- Серия (как Stoic): день засчитывается за ЛЮБУЮ активность — чек-ин, отметка аскезы/ритуала, запись «Настроения». «Пройти заново» серию не увеличивает. Считает фронт; прошлые отметки практик — GET /api/practice-days (бэкенд #86).
- Календарь недели без галочек (#805). Вопрос владельцу «вернуть ✓ как у Stoic?» — открыт.
- Подсказки: закрываются крестиком или сами, когда пролистаны за экран (не исчезают во время прокрутки).
Чек-ин
- Утро: настроение → энергия → «Что на уме?». Шкалы без автоперехода: «Далее» + «Пропустить». «Эмоции» — вертикальный столбец pill, тяжёлая эмоция → mayak.
- Завершение разбора: «Сохранить» главная, «Разобрать со Следопытом» второстепенная.
Практики
- Аскезы/ритуалы — вариант C (#809): плитки в 2 колонки, отмеченная сегодня — светлая; без чисел и серий. Экран практики: крупная плитка-кнопка + «Зачем / Как / Заметка»; у аскезы «Сорвался сегодня». Тап отмечает: ритуал полным уровнем, аскеза «удержал».
- Практика «Настроение» — отдельная запись, видна в истории под чек-ином дня, засчитывается в серию.
- Практики по умолчанию новому аккаунту не добавляются.
Профиль и прочее
- Монохром; группы НАСТРОЙ → АККАУНТ → ПОМОЩЬ → ПРИЛОЖЕНИЕ; три баннера с персонажем. Поддержка — t.me/smira31.
- Заголовки экранов строчные с точкой: «твои практики.», «о тебе.», «подписка.».
- Масштаб приложения запрещён (щипок, двойной тап, автозум полей ввода).
- Жесты: свайп от левого края = «Назад» на вложенных экранах; шторки — свайп вниз. В Telegram без своего ✕ у шторки серии.

## 6. Опыт с агентами (важно)
- Новая задача = новый импорт Base44 («+» → Bring your own project → репо → ветка). Старый чат не переиспользовать — он складывает задачу в старую ветку/PR.
- Base44 сам называет ветки (fix-no-zoom, pr-preview-workflow…) — смотреть имя в отчёте.
- Агент кончился — новый импорт на ТОЙ ЖЕ ветке, промпт «продолжи, готовое не переделывай».
- Сообщения «Напишите continue» — владелец отвечает continue сам, ассистенту не несёт.
- Агенты врут про «предсуществующие» падения — проверять: в main 0 падений.
- Агенты путают номер PR — сверять ветку.
- Сборка в контейнере Base44 падает на top-level await в tgShell.js — это окружение; арбитр — Checks в PR. src/main.jsx и src/tgShell.js не трогать (CI запрещает).
- Тесты с жёстко зашитыми датами ломаются на следующий день — даты только относительно текущего дня.
- Агент может самовольно «улучшить» дизайн (нарисовал птицу Stoic) — в промпте запрещать менять то, что не просили.
- После деплоя в Telegram старая версия — очистить кэш Telegram.

## 7. Оркестрация: ассистент + 3 агента (с 25.09.2026)
Любой ассистент (Claude в новом чате, другой аккаунт, ChatGPT) может взять эту роль, прочитав этот файл и docs/STATUS.md.
- Экран владельца: слева ассистент-оркестратор, справа три окна Base44 (разные аккаунты): A = Awersegy (правое верхнее), B = Blacksmira (левое нижнее), C = Wtfdone (правое нижнее). Владелец начинает сообщение с «A:», «B:», «C:»; ассистент отвечает промптом для той же буквы.
- Зоны, чтобы агенты не мешали друг другу (одновременно — только разные зоны):
  • A — «Сегодня», чек-ин, разбор, серия/огонёк;
  • B — практики, Библиотека, Диалог/Следопыт, Профиль, История;
  • C — инфраструктура: тесты, CI, превью, робот-обход, демо-панель, скорость, бэкенд mentalix-bot (бэкенд — только один агент за раз).
  Задача на стыке зон — только одному агенту, остальные в это время берут другую зону.
- Одна задача = новый импорт Base44 от свежего main = одна ветка = один PR. Агент кончился — новый импорт на ТОЙ ЖЕ ветке, «продолжи, готовое не переделывай».
- Промпт короткий: ветка + задача + «проверить на iPhone по ссылке превью». Стандарт работы агент берёт из AGENTS.md.
- docs/STATUS.md в фичевых PR НЕ править (иначе конфликты между параллельными PR). Доску ведёт оркестратор: копия в проекте Claude, в репозиторий — отдельным маленьким PR раз в день.
- Мерж по одному. После каждого мержа в остальных открытых PR нажать «Update branch» (или агенту: git merge origin/main). Конфликт — агенту той ветки: «git merge origin/main, сохрани обе стороны».
- Проверка: 1) Checks в PR зелёные (visual snapshots — informational, можно красный); 2) владелец открывает на iPhone ссылку превью бота Firebase (mentalix-production--pr-N-….web.app/?demo=1, с &panel=1 для демо-панели) — НЕ base44-preview; 3) после рискованных мержей (точка входа, жесты, прокрутка) — проверка в Telegram с очисткой кэша.
- Ассистент экономит токены: не пересказывает, не разбирает PR глубоко, проверяет только ветку/тесты/конфликты (git), отвечает коротко. Сообщения агентов «напишите continue» владелец отвечает сам.
- Длинный чат дорог: новый чат с ассистентом раз в день или после 3–4 PR; первое сообщение — «Прочитай передачу контекста и доску задач, продолжаем». Перед уходом из чата ассистент обновляет этот файл и доску в проекте Claude.

## 8. Слепые пятна (учтены)
- Агенты правдоподобно отчитываются «всё зелёное», а на iPhone не работает: Playwright не умеет настоящий свайп пальцем в WebKit. Жесты/прокрутка — только финальная проверка владельцем на iPhone.
- Base44 путает номера PR и даёт свои имена веткам, даёт ссылку base44-preview вместо Firebase — сверять ветку и ссылку.
- Агент может «улучшить» то, что не просили (птица вместо персонажа, отступ 46→16) — в промпте: «не менять то, что не просили»; утверждённые значения держат контрактные тесты.
- Промпт, вставленный не в тот чат, попадает в чужую ветку/PR (так было с документами в демо-панели) — сверять букву окна.
- Разные аккаунты Base44: каждому нужен доступ к GitHub Smira31; лимиты у каждого свои.
- Изменение схемы БД — только с готовым SQL для Neon, выполняет владелец.
- src/main.jsx — точка входа; правка только с меткой allow-entry-change и проверкой в Telegram после мержа.

## 7. Оркестрация: ассистент + 3 агента
- Владелец держит 4 окна: слева ассистент (оркестратор), справа три агента Base44 в режиме «приложение»: A (аккаунт Awersegy), B (Blacksmira), C (Wtfdone). Отчёт владелец присылает с буквой «A:/B:/C:», ассистент отвечает промптом с той же буквой.
- Одно окно = одна ветка = один PR. Новая задача = новый импорт Base44 (от main или от ветки, если продолжение). Какая ветка у какого агента — в docs/STATUS.md, раздел «В работе».
- Чтобы агенты не мешали друг другу: параллельно давать только задачи на РАЗНЫЕ экраны/файлы. Общие файлы (App.jsx, index.css, Today.jsx, demoMode.js, series.js, AGENTS.md) — в одну задачу за раз. Если два PR трогают одно — мержить по очереди, второй агент делает git merge origin/main.
- После каждого мержа в main остальные агенты перед финалом делают git merge origin/main.
- Промпты короткие: стандарт — в AGENTS.md; в промпте только буква, ветка, задача, что прислать.
- Ассистент экономит токены: не перечитывает весь репозиторий, проверяет только суть (ветка, тесты, конфликты), отвечает коротко. Ответ «continue» агентам владелец даёт сам.
