# MXL-UI — системный UI-аудит

Дата среза: 13.08.2026

Baseline: `b25c8e3` (`main` после закрытия MXL-GLYPH-UNIFY-001)

Целевой интерфейс: dark-only, Telegram-first, web fallback

Основной контрольный viewport: `320 × 568`

## Результат

Критических P0-дефектов в доступном web-сценарии не найдено. Зафиксированы пять
конкретных P1-находок: три нарушения мобильной композиции, одно нарушение
доступности и один системный технический риск полноэкранных поверхностей.

Аудит не меняет продуктовую логику, тексты, токены, API или backend. Исправления
должны идти отдельными короткими циклами с независимой проверкой.

## Pre-mortem

Представленный сценарий провала: через несколько недель «системный аудит» всё ещё
идёт, список растёт, субъективные визуальные пожелания смешались с багами, а
проверенные в браузере поверхности ошибочно названы проверенными в Telegram.

### Тигры — предусловия работы

1. **Бесконечный субъективный редизайн.** Аудит ограничен одним статическим проходом
   и одним mobile-runtime проходом. В отчёт входят только воспроизводимые дефекты,
   нарушения нормативов или явно обозначенные пробелы покрытия.
2. **Ложное полное покрытие.** Для каждого класса экранов указан уровень проверки:
   runtime, static-only или требуется реальное устройство. Недоступный state не
   считается проверенным живьём.
3. **Смешение исправлений с продуктовыми решениями.** В этой задаче нет правок UI.
   Находка, требующая нового текста, токена, поведения или API, сначала получает
   отдельное согласование.
4. **Большой нереверсивный пакет.** Каждый следующий цикл исправляет одну связанную
   группу симптомов и имеет отдельный commit/PR. API, данные и навигация не меняются.
5. **Пропуск Telegram-специфичных дефектов.** Web-проверка не закрывает fullscreen,
   safe area и клавиатуру Telegram. Такие изменения не мержатся без реального
   iPhone/Telegram gate.

### Слон в комнате

«Проверить весь UI» невозможно закрыть навсегда: состояния зависят от данных,
платформы и будущих функций. Definition of Done этого прохода — конечный инвентарь,
приоритеты, доказательства и безопасная очередь исправлений, а не обещание, что в
приложении больше нет UI-дефектов.

### Бумажные тигры

- Приватный backend не блокирует визуальный аудит, пока не меняются контракты и
  серверные состояния.
- Light mode неприменим: продукт нормативно dark-only.
- Карточки «Скоро» не требуют запуска скрытых функций; их видимая оболочка проверяется
  отдельно, скрытые экраны остаются static-only.

## Метод и покрытие

Проведены:

- инвентаризация `src/screens/**`, `src/components/**` и маршрутизации в `App.jsx`;
- статическая проверка токенов, текстовой прозрачности, Telegram-импортов,
  полноэкранного контракта, полей ввода и доступных имён контролов;
- runtime-проход web fallback на `320 × 568`: web auth, онбординг, Сегодня,
  Практики, пустые состояния и форма Ритуалов, пустое состояние Аскез,
  выбор AI-персоны, Библиотека, Аналитика, Настройки;
- проверка геометрии конфликтующих элементов через фактические DOM-границы.

## Находки

### MXL-UI-001 — элементы шапки перекрывают заголовок на 320 px — P1

На экране «Сегодня» правая граница кнопки «Нить дня» находится на `x=98`, а
заголовок начинается на `x=89.16`: пересечение около `8.84px`. В Настройках кнопка
«Назад» заканчивается на `x=111.64`, заголовок начинается на `x=106.16`:
пересечение около `5.48px`. Оба конфликта видимы на скриншоте и воспроизводятся
без изменения данных.

**Безопасный цикл:** общий контракт мобильной шапки для этих двух экранов;
сохранить текущие тексты, действия, safe area и высоту контента. Проверить `320 × 568`,
`390 × 844` и реальный Telegram/iPhone.

### MXL-UI-002 — CTA AI-персоны уходит под нижнюю навигацию — P1

На `320 × 568` карточка персоны имеет `clientHeight=358` при `scrollHeight=419`.
Кнопка «Говорить» расположена по `y=476.61…527.11`, нижняя навигация начинается
на `y=494`: около `33px` основного действия пересекается с навигацией. Это
затрудняет считывание и нажатие ключевого действия.

**Безопасный цикл:** адаптировать вертикальную композицию карточки к короткому
viewport без изменения карусели, пропорции смыслового глифа и текста. Проверить
все три персоны, reduced motion и iPhone/Telegram.

### MXL-UI-003 — «Нейротренажёр» обрезается в сетке Практик — P1

На `320 × 568` заголовок видимой locked-карточки отображается как
«Нейротренаж…». Причина — двухколоночная карточка шириной около `135px`, внутренние
горизонтальные отступы `18px` и однословный заголовок без стратегии переноса.
Статус «Скоро» не снимает проблему: карточка остаётся частью основного экрана.

**Безопасный цикл:** выбрать локальную стратегию для длинного названия без смены
копирайта и без изменения всей сетки. Проверить остальные пять карточек на обеих
контрольных ширинах.

### MXL-UI-004 — переключатели Настроек не имеют доступного имени — P1

Оба icon/text-less `button` в `Settings` (`Напоминание от бота`, `Блокировка
приложения`) не имеют `aria-label`, `title` или switch-семантики. В accessibility
tree они представлены как безымянные кнопки.

**Безопасный цикл:** добавить `type="button"`, доступное русское имя, `role="switch"`
и `aria-checked`; визуал и поведение не менять.

### MXL-UI-005 — две fullscreen-поверхности обходят единый контракт — P1

`src/screens/mentalix/Conversation.jsx` и `src/screens/CheckIn.jsx` независимо
дублируют `visualViewport`, `position: fixed`, блокировку body и/или Telegram offset
вместо `useFullscreenSurface`. Это нарушает обязательный архитектурный контракт и
создаёт риск расхождения при клавиатуре, fullscreen и safe area. На web-прогоне
Telegram-специфичный симптом не проверялся.

**Безопасный цикл:** сначала Characterization QA на реальном iPhone для обоих
сценариев, затем миграция по одному экрану на `useFullscreenSurface`, без изменения
UI или API; после каждого экрана — клавиатура, скролл, возврат, повторное открытие.

## Подтверждённые инварианты

- запрещённых импортов `@twa-dev/sdk` вне `src/platform/**` нет;
- статических классов прозрачности для `text-cream/text-muted/text-faint` нет;
- горизонтального переполнения документа на `320 × 568` в проверенных состояниях нет;
- проверенные поля формы Ритуала и поиска Библиотеки имеют вычисленный размер `16px`;
- gold остаётся единственным акцентом, новые токены и цвета не вводились;
- нижняя навигация имеет доступные русские имена пяти вкладок.

## Очередь исправлений

1. **Цикл A — мобильная шапка:** MXL-UI-001.
2. **Цикл B — ключевое действие AI:** MXL-UI-002.
3. **Цикл C — доступность Настроек:** MXL-UI-004.
4. **Цикл D — карточка Практик:** MXL-UI-003.
5. **Цикл E — fullscreen-консолидация:** MXL-UI-005, строго по одному экрану.
6. После A–E — реальный iPhone/Telegram regression pass и измеряемый пользовательский
   тест core loop по ROADMAP.

## Критерий закрытия MXL-UI

- каждый P1 прошёл отдельный минимальный цикл и обязательные проверки;
- нет новых P0/P1 в затронутых сценариях;
- static-only и data-dependent поверхности не названы проверенными без факта;
- итоговый regression pass подтверждён владельцем на реальном iPhone/Telegram;
- после этого следующий этап — продуктовые события и пользовательский тест, а не
  новый бесконечный визуальный проход.
