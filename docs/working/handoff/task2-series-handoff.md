## Сломано сейчас

Последний запуск выбранных unit-тестов завершился с ошибками до последних двух точечных правок:

- `tests/unit/series.test.mjs`: `buildSeriesViewModel` возвращал `bestStreak = 1` вместо серверного исторического значения `4`; исправлено возвратом `metrics.best_streak` с совместимостью через `Math.max(история, серверное значение)`.
- `tests/unit/series-badges-navigation-contract.test.mjs`: старый контракт запрещал `X` и `.mx-path-close`, хотя §5.3 требует явную кнопку закрытия; тест обновлён под новый контракт.
- `tests/unit/visual-viewport.test.mjs`: в первом запуске не находился пакет `react`, потому что зависимости ещё не были установлены. Затем выполнен `npm install`; visual-viewport после установки не был перезапущен.

После этих последних правок проверки намеренно не перезапускались по просьбе владельца остановить работу. Поэтому текущая зелёность не подтверждена.

## Принятые решения

- Серверные `best_streak`, `days_active` и `total_checkins` сохраняются как совместимый исторический fallback, но при наличии истории вычисленные значения имеют приоритет через `Math.max`. Это не ломает старые ответы профиля, где история ограничена или неполна.
- Дата API-поля `checkin.date` считается уже нормализованной backend-договором датой пользователя. Timestamp без `date` преобразуется через переданный timezone профиля.
- Настройки показа серии и подсказка хранятся локально в `localStorage`, потому что задача касается Telegram iOS UI и backend-контракт для этих preferences не задан.
- PWA/Safari-код не менялся намеренно; изменения входов серии ограничены Today и fullscreen-экраном серии.
- Для этой задачи не добавлялись motion-анимации шторок, поскольку §6 вынесен в отдельную задачу.
