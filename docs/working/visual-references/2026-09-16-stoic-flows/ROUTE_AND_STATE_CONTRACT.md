# Mentalix — контракт маршрутов по видео Stoic

Статус: визуальная спецификация, не продуктовый код. Целевое устройство — iPhone 16 Pro Max, физический PNG `1320×2868`.

## Что переносим из референса

- один главный шаг на экране;
- короткую последовательность состояний вместо длинной формы;
- компактную библиотеку строк для выбора практики;
- полноэкранную практику дыхания с одним центральным объектом;
- нижнюю панель редактора, прижатую к клавиатуре через `visualViewport`;
- отдельное честное завершение с нейтральной обратной связью.

Не переносим бренд Stoic, английский текст, фиолетовый акцент, птиц, paywall, Premium-замки, чужие иллюстрации, теги/медиа, новые API и обещания синхронизации.

## Сценарий A — ежедневный check-in

Точка входа уже существует: `Сегодня → Пройти чек-ин`.

| Состояние | Экран | Действие | Следующее состояние |
|---|---|---|---|
| `mood` | `02-checkin-mood-after.png` | выбрать одно состояние | `energy` |
| `energy` | та же композиция, вместо лиц пять уровней энергии | выбрать уровень | `focus` |
| `focus` | компактный выбор существующего фокуса дня | выбрать один вариант или пропустить | `writing` |
| `writing` | `04-checkin-editor-after.png` | написать ответ и нажать стрелку | следующий существующий вопрос / `complete` |
| `complete` | `05-checkin-completion-after.png` | оценить полезность необязательно; «Сохранить и завершить» | `Сегодня`, состояние дня обновлено |

Правила:

- не менять существующий payload `CheckIn`, API и семантику сохранения;
- число шагов и сами вопросы берутся из текущего режима (`checkin`, утро, вечер), а не из PNG;
- прогресс отражает реальные шаги;
- Back возвращает на предыдущий шаг и не записывает completion;
- Close закрывает поток по существующему контракту;
- feedback на финале необязателен и не блокирует завершение;
- панель над клавиатурой располагается вплотную к `visualViewport`, без большой мёртвой зоны;
- никаких дополнительных внутренних кнопок «Назад», нижней навигации и transform/fade вспышек.

## Сценарий B — практики

Точка входа уже существует: основная вкладка `Шаги`.

| Состояние | Экран | Действие | Следующее состояние |
|---|---|---|---|
| `catalog` | `07-practices-home-after.png` | открыть журнал, одну из практик, тему недели или «Все практики» | существующий flow / `library` / `theme` |
| `library` | `09-practices-library-after.png` | выбрать существующую практику | соответствующий существующий `sub` |
| `breathing` | `10-breathing-active-after.png` | пройти/остановить дыхание | нейтральный outcome → назад в каталог |
| `theme` | `11-weekly-theme-after.png` | выбрать день и «Начать запись» | существующий `ThemeScreen` editor |
| `theme-writing` | визуальная грамматика `04-checkin-editor-after.png` | сохранить запись | существующий completion темы |
| `theme-complete` | визуальная грамматика `05-checkin-completion-after.png` | завершить | назад в каталог/Сегодня по текущему контракту |

Правила:

- использовать только реальные маршруты из `Practices.jsx`: `journal`, `first-step`, `no-blame`, `narrow-focus`, `one-finish`, `meditation`, `breathing` и другие уже существующие;
- не добавлять отдельный router, шестую вкладку или новый backend-каталог;
- `Все практики` — локальное представление существующего списка, не новый серверный объект;
- переиспользовать `SemanticGlyph`/`CardSystemGlyph`, `JournalTextarea`, `useFullscreenSurface`;
- недельная тема использует реальные `WEEKLY_THEME_CATALOG` и `ThemeScreen`;
- дыхание использует текущую механику `Breathing.jsx`; меняется визуальная композиция, а не таймер/события;
- остановка дыхания нейтральна и не считается успешным completion;
- нижняя навигация видна только в основном каталоге; внутри fullscreen её нет.

## Обязательные состояния проверки

- loading / error / empty для текущих данных;
- 320 px, iPhone 16 Pro и iPhone 16 Pro Max;
- Telegram Mini App и web fallback;
- открытая русская клавиатура;
- длинный русский вопрос и длинный ответ;
- Back, Close, early cancel, interrupted breathing;
- reduced motion;
- отсутствие двойного body scroll и скачка viewport.
