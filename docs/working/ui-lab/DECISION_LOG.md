# UI Lab — decision log

Этот журнал отвечает на вопрос: **какое решение принято по результатам UI Lab и что из него следует**. Он не заменяет канонический реестр продуктовых решений в [`docs/core/PRODUCT_DECISIONS.md`](../../core/PRODUCT_DECISIONS.md), а хранит рабочую трассировку UI Lab.

## Формат

Каждая запись содержит дату, решение, evidence, границы и следующий gate. Решение должно быть проверяемым и не должно подразумевать изменение production, если это не написано явно и не оформлено отдельным PR.

## Решения

### `UI-DEC-004` — symbolic flat illustration и динамическая пара Gold ↔ Azure

- **Дата:** 03.09.2026
- **Статус:** принято владельцем
- **Решение:** для карточек принят принцип **Mentalix Symbolic Flat Illustration**: глиф — узнаваемая символическая метафора смысла практики, не буквальная UI-иконка и не чистая абстракция, собранная из 3–7 крупных форм с большим количеством воздуха. Визуальный язык сочетает спокойный тонкий line-art и крупные flat-заливки без градиентов, 3D, текстур, неона, фотореализма, generic-иконок и человеческих персонажей. Акцентная точка выбирается из динамической пары Gold (`--c-gold`) ↔ Azure (`--c-azure`); одновременно допускается не более одной точки-акцента. Аватар Mentalix — исключение и всегда Gold.
- **Обоснование:** этот принцип сохраняет смысловую узнаваемость глифов, но не превращает их в готовые UI-пиктограммы или декоративную абстракцию; пара акцентов позволяет теме/пользователю выбирать цвет без изменения семантики композиции.
- **Граница:** конкретные сюжеты глифов разрабатываются отдельно product/design-стороной; этот лог и `DESIGN_SYSTEM.md` фиксируют только принцип отрисовки. `--c-azure: #6FB7E0` — временное значение до подтверждения точного hex дизайнером.

### `UI-DEC-005` — каталог «Практики» переходит на паттерн «Ярусный каталог»

- **Дата:** 03.09.2026
- **Статус:** принято владельцем
- **Решение:** конфликт «Тихая сетка vs horizontal-rail» закрыт в пользу многоярусной композиции «Ярусный каталог»: герой-баннер, горизонтальный рельс «Новое и рекомендованное», карусель «Тема недели», 2-колоночная сетка «Коллекции» и bottom-sheet «Чек-ин эмоций». Для каталога «Практики» этот паттерн заменяет прежнее сопоставление с «Тихой сеткой»; «Тихая сетка» сохраняется для Ритуалов, Аскез и Библиотеки.
- **Обоснование:** многоярусная композиция одновременно даёт промо-зону, горизонтальное открытие нового/рекомендованного контента, тематический фокус, коллекции разной плотности и контекстный check-in, не сводя каталог к одному каркасу.
- **Граница:** зафиксирован только документальный и визуальный принцип. Компоненты каталога, глифы и bottom-sheet не реализуются этой задачей; production promotion требует отдельного PR и manual gate на реальном Telegram/iPhone.

- **Дата:** 03.09.2026

Эксперимент включает hero-баннер, настоящий горизонтальный rail со snap, переключаемую карусель «Тема недели», статичную сетку «Коллекции» и bottom-sheet «Чек-ин эмоций».
- **Обоснование:** сравнение в одном viewport делает разницу между текущей последовательной навигацией и многоярусной композицией проверяемой до любых изменений production.

- **Следующий шаг:** ручной Telegram/iPhone gate: safe areas, размеры, swipe/snap, keyboard/focus, bottom-sheet и отсутствие overflow. До успешного gate перенос в production запрещён.

### `UI-DEC-002` — DailyCanonicalExperiment собран из реальных источников; «Смысловая мозаика» не интегрирована

- **Дата:** 03.09.2026
- **Статус:** принято владельцем
- **Решение:** `DailyCanonicalExperiment` (`?ui_lab=daily-canonical`, `MXL-DAILY-CANONICAL-UI-LAB-001`) реализован как Preview-only сборка полного дневного цикла (Welcome → Check-in → Morning Check-in → Today/dayInProgress → completion → Today/reviewPending → Evening Review → Today/dayClosed → Next Day) из уже существующих UI Lab прототипов: узлы Today рендерятся через реальный prod `Today.jsx` (тот же приём, что уже использует `TodayStatePreview.baseline`), Morning Check-in портирован из PR #498, Evening Review уже в `main`. Владелец явно подтвердил (03.09.2026): узлы Today используют реальный `Today.jsx`, а не «Смысловую мозаику» (`MeaningBentoPreview` из `CardDirectionsLab.jsx`) — на момент решения `MeaningBentoPreview` существует только как невыгружаемая статическая mock-верстка внутри самого `CardDirectionsLab.jsx`, без привязки к реальным данным/fixture; вынос её в отдельный exported/data-driven компонент остаётся нерешённой задачей. По ходу реализации найден и исправлен баг: Exit из Morning Check-in (портированного из PR #498 без изменений) вызывал только внутренний `reset()` компонента, а не выход из чек-ина — пользователь оставался запертым внутри модалки. Добавлен опциональный проп `onExit` (по тому же паттерну, что `onComplete`/`onDayClosed`): при передаче Exit реально возвращает на Today/checkinPending; без `onExit` старое поведение сохранено для других потребителей компонента.
- **Evidence:** коммиты `732405ae`, `78e2b90e`, `d3a395e2` на ветке `feature/mxl-daily-canonical-ui-lab-001` (не запушена); `tests/ux/mxl-daily-canonical-ui-lab-001.spec.mjs` — 9/9 PASS (полный флоу на 320/390/430px, debug-переходы, Morning Check-in Exit → реально возвращает на Today/checkinPending, Back с середины wizard'а — обычный шаг назад, reload на середине флоу, keyboard-only навигация, `prefers-reduced-motion: reduce`); `npm run check:core` зелёный.
- **Не следует из решения:** это не production promotion и не финальный визуальный язык Today — Preview-only сборка, реальный Telegram/iPhone manual gate не проходился; вопрос интеграции «Смысловой мозаики» остаётся открытым, а не отклонённым.
- **Следующий шаг:** owner-decision — нужна ли «Смысловая мозаика» для узлов Today в этом флоу, или реальный `Today.jsx` остаётся достаточным reuse-источником; если да — отдельная задача на выгрузку `MeaningBentoPreview` из `CardDirectionsLab.jsx` в exported data-driven компонент.

### `UI-DEC-003` — реальный Telegram/iPhone gate: найден и исправлен header overlap; найден и НЕ исправлен унаследованный дубль кнопок в CheckIn.jsx

- **Дата:** 03.09.2026
- **Статус:** принято владельцем (gate пройден владельцем вручную на iPhone в реальном Telegram Mini App)
- **Решение:** по итогам ручного gate исправлен один баг в нашем коде и явно НЕ исправлен один найденный баг в предсуществующем коде.
  - **Исправлено (наш код):** `DailyCanonicalExperiment.jsx` не использовал Telegram safe-area вообще. Причина — `?ui_lab=*` не монтирует `App.jsx` (`main.jsx` рендерит `<UiLab>` вместо него), а Telegram fullscreen/safe-area negotiation (`src/lib/tgFullscreen.js`) сама по себе стартует только из `App.jsx` или из первого вызова `useFullscreenSurface()` — то есть только когда пользователь открывает Morning Check-in. До этого момента `--app-safe-top` не учитывал высоту нативной Telegram-шапки, и заголовок «Дневной цикл целиком», стоящий в обычном потоке страницы (не portal), успевал отрисоваться под ней на Welcome/checkinPending. Исправлено подпиской на тот же общий store (`subscribeFullscreen`/`getFullscreenSnapshot`) прямо в `DailyCanonicalExperiment` и применением того же паттерна отступа, что уже использует `useFullscreenSurface` (`calc(var(--app-safe-top) + 56px)` в fullscreen-состоянии).
  - **НЕ исправлено, унаследованный баг (пре-existing):** экран с дублирующимися парами кнопок «Дальше»/«Пропустить» и «Закрыть день»/«Пропустить» — это не `EveningReviewExperiment`, а реальный prod `src/screens/CheckIn.jsx` (mode `evening`), открывается собственной кнопкой внутри самого `Today.jsx` (`changeSub('checkin')`, `Today.jsx:547-556`), никак не связанной с нашим кодом. `CheckIn.jsx` рисует действие на каждом шаге дважды: нативными Telegram `useMainButton`/`useSecondaryButton` и DOM-компонентом `<WebActionBar>`; `WebActionBar.jsx:25` обязан гаситься условием `platformName === 'telegram'` — если обе пары видны одновременно, это значит `platformName` (`src/platform/index.js`, детект по `window.Telegram?.WebApp?.initData`) в тот момент не равнялся `'telegram'`. `git diff main...feature/mxl-daily-canonical-ui-lab-001` по `CheckIn.jsx`, `Today.jsx`, `WebActionBar.jsx`, `platform/index.js`, `platform/telegram.hooks.js` — пусто, эта ветка их не трогала. Не чинили по прямому указанию владельца — предсуществующий код, требует отдельного решения и починки вне этой задачи.
  - Побочное наблюдение (не бага ради, для контекста, не тронуто): на `reviewPending` рядом стоят две похожие кнопки «Разобрать день» — своя у `Today.jsx` (ведёт в реальный `CheckIn.jsx`) и наша bridge-кнопка (ведёт в `EveningReviewExperiment`) — вероятная причина, почему владелец попал именно на `CheckIn.jsx`.
  - Отдельно по ходу проверки найдена и исправлена флейкинность в **нашем тесте** (не в приложении): `tests/ux/mxl-daily-canonical-ui-lab-001.spec.mjs` проверял continuity на `Today/dayClosed` через текст `MorningPilotCard` («До других дел»), а та карточка — реальный prod-компонент, показывается только в окне 5:00–11:59 по времени устройства (`src/lib/morningPilot.js`, `isMorningPilotTime`). Тест переписан на time-independent проверку (`data-phase` + hero-текст «День закрыт»); continuity на `dayInProgress`/`reviewPending` и так уже проверяется через time-independent hero-текст.
- **Evidence:** коммит `0f8059c8` на ветке `feature/mxl-daily-canonical-ui-lab-001` (не запушена); `npm run ux:daily-canonical` — 9/9 PASS после обоих изменений; `npm run check:core` зелёный.
- **Не следует из решения:** унаследованный баг CheckIn.jsx не считается закрытым и не блокирует merge Daily Canonical — это существующий production-риск, обнаруженный впервые именно через этот gate, а не что-то, что появилось из-за этой ветки.
- **Следующий шаг:** owner-decision — заводить ли отдельную задачу на диагностику `platformName`/`WebActionBar` дублирования в `CheckIn.jsx` (вне UI Lab, вне этой ветки).

### `UI-DEC-008` — «Тихая типография» для Trends и соседних preview-поверхностей

- **Дата:** 03.09.2026
- **Статус:** принято для этого UI Lab эксперимента
- **Решение:** для блока Trends в `HistoryTrendsJournalExperiment` принят визуальный принцип «линия/точка вместо заливки»: безрамочные data-блоки, текстовые tabs, вертикальный ритм 34–36px и максимум один золотой акцент на смысловой блок. Bar chart использует тонкие линии и точки, heatmap — контурные круги с одним заполненным днём, ring chart — тонкое кольцо с числом вне SVG. Тот же принцип ритма, сдержанной иерархии и отсутствия лишних card-background применён к History и Journal в этом же эксперименте.
- **Обоснование:** line/dot вместо fill снижает визуальный шум и оставляет цифрам и подписям ведущую роль; безрамочные блоки делают Trends аналитическим чтением, а не набором декоративных карточек; текстовые tabs сохраняют состояния без лишних пилюль и конкурирующих акцентов.
- **Локальные токены:** значения `#050403`, `#f5f1ea`, `#837c70`, `#6b6558`, `#56514a`, `#cda45e`, `#34302a`, `#241f18`, `#1c1812` заданы локально в `HistoryTrendsJournalExperiment.css`; глобальные переменные `DESIGN_SYSTEM.md` не переопределяются. Для текста сохранён актуальный проектный шрифт `Onest`, а не временный `Manrope` из референса.
- **Границы:** это только Preview-only UI Lab; пять существующих карточных семейств и production-экраны не меняются. Перенос направления в production требует отдельного PR и обязательного Telegram/iPhone manual gate.
- **Evidence:** `feat/ui-lab-history-trends-journal`, PR #502; локальная спецификация из `pasted_content.txt`.
- **Следующий шаг:** проверить Trends на целевых ширинах и в reduced-motion, затем собрать owner feedback перед решением о дальнейшем продуктовом переносе.
