## 2. Общая визуальная грамматика трёх видео

### 2.1. Композиция

- Чёрный фон экрана и спокойные графитовые поверхности без декоративных градиентов.
- Один крупный lowercase-заголовок экрана; справа — только контекстные действия.
- Контент строится ярусами: заголовок → основной блок → тематические секции → карточки.
- Карточки преимущественно крупные, с радиусом 24–28 px, тонкой границей или разницей поверхности вместо тяжёлой тени.
- Сетки используют две колонки с одинаковым ритмом и редкими асимметричными иллюстрациями.
- Горизонтальные последовательности показывают край следующей карточки; жест реализуется нативным overflow + `scroll-snap`, без document-level touch handlers.
- Bottom navigation остаётся плавающей поверхностью над контентом; её контракт принадлежит `App.jsx` и не меняется экраном.

### 2.2. Типографика Mentalix

- Не копировать гарнитуру Stoic. Основной шрифт Mentalix — `Onest`; caps-лейблы — `Manrope` через `font-label`.
- Заголовок экрана: текущий `mx-type-page`, lowercase, Onest.
- Заголовки карточек: Onest 600/700, без чрезмерного увеличения.
- Эйбраузы и категории: `font-label`, 10–11 px, uppercase, увеличенный tracking.
- Вторичный текст использует `text-muted`/`text-faint`, а не статическую opacity.
- Все product-facing строки — только на русском.

### 2.3. Цвет и иллюстрации

- Использовать только токены Mentalix: `--c-bg`, `--c-card`, `--c-card2`, `--c-text`, `--c-muted`, `--c-faint`, `--c-border`.
- Значимый акцент — Gold или Azure по семантике Mentalix; фиолетовый Stoic и premium-градиент не переносить.
- Иллюстрации переводятся в `CardSystemGlyph`/`SemanticGlyph`: тонкая контурная геометрия, 3–7 крупных форм, одна смысловая точка-акцент.
- Не копировать перо Stoic, фирменные персонажи, конкретные обложки, premium-бейджи и узнаваемые иллюстрации.

### 2.4. Motion и платформенное поведение

- Переходы целого экрана — opacity; не двигать и не масштабировать viewport.
- Нажатие карточки: 140–240 ms через конкретные `transform`/`opacity`, без `transition: all`.
- Горизонтальные rail и paging работают через CSS scroll snap.
- `prefers-reduced-motion` оставляет полностью читаемую статичную композицию.
- Сохраняются Telegram safe-area, 56 px зоны системных контролов и нижний резерв навигации.

### 3.3. Предлагаемая структура UI Lab #526

Первый UI Lab проверяет **одну проблему**: пользователь должен быстро понять, что хранится в Библиотеке, и открыть нужный существующий тип материала.

1. **Header**
   - `библиотека.` слева;
   - круглая кнопка поиска справа;
   - поиск раскрывается в строку внутри потока, не создаёт новый fullscreen overlay.
2. **Featured rail «Продолжить»**
   - показывается только при наличии незавершённой направленной записи или материала в процессе;
   - если данных нет, ярус полностью отсутствует — фиктивный прогресс не рисовать.
3. **Ярус «Для тебя»**
   - реальные статьи из существующего массива, без новой персонализации;
   - крупная первая карточка и видимый край следующей;
   - карточка открывает существующий reader.
4. **Секция «Коллекции»**
   - две активные входные карточки: «Статьи» и «Направленные записи»;
   - третья карточка «Практикумы» остаётся disabled с подписью «СКОРО»;
   - в UI Lab допустимы fixtures только для геометрии, production обязан использовать реальные состояния.
5. **Каталог выбранного типа**
   - центрированный eyebrow + заголовок + короткое описание;
   - статьи: реальный поиск и текущие article cards в новой сетке/rail;
   - записи: существующие поиск, категории, продолжение, архив и шаблоны;
   - возврат через существующий `BackButton`/локальное состояние, без router package.

### 3.4. Состояния

- `loading`: skeleton той же геометрии; не заменять экран одной строкой.
- `error`: компактный встроенный блок + текущая команда «Повторить».
- `empty`: объяснить, что появится здесь, и показать только существующее доступное действие.
- `search empty`: «Ничего не найдено» + способ очистить запрос.
- `disabled`: «Практикумы · СКОРО», без клика, haptic и ложного открытия.
- `web fallback`: статьи работают; направленные записи честно показывают существующее Telegram-only ограничение.

## 4. `IMG_6009` — сохранённый контракт «Истории»

Этот блок зафиксирован для будущего, но не входит в #526 и не разрешает новый PR.

### Наблюдения

- `00:00–00:03`: записи сгруппированы по дням; сверху переключатель масштаба, фильтр и поиск.
- `00:02–00:04`: detail записи — свободная вертикальная композиция без карточки вокруг всего контента.
- `00:05–00:11`: карточки различной высоты в зависимости от содержания; mood tags остаются внутри записи.
- `00:08–00:10`: achievement открывается как bottom sheet поверх затемнённой History, а не как новая вкладка.
- `00:12–00:17`: переключение `Days → Weeks`; недели группируются по месяцам и показывают краткие счётчики типов записей.

### Mentalix interpretation

- Сохранить уже существующую группировку истории и реальные типы записей.
- Возможный будущий проход: day/week presentation, поиск/фильтр и detail без общей тяжёлой оболочки.
- Не копировать achievement sharing, если такого product contract нет.
- Не объединять с #526 и не менять persistence/API без отдельной задачи.

## 5. `IMG_6010` — сохранённый контракт #527 «Прогресс»

Не начинать до закрытия #526.

### Наблюдения

- `00:00–00:05`: period selector `Weeks / Months / Years`, крупный заголовок и один главный line chart.
- `00:06–00:12`: секция общих наблюдений, карточка ведущей активности и календарь состояния.
- `00:12–00:18`: отдельный ярус эмоций; insight-карточки сохраняют одинаковую геометрию даже при отсутствии данных.
- `00:18–00:27`: типы активности разделены на самостоятельные карточки с локальным переключателем метрики.
- Внизу закреплён period navigator; он не должен перекрывать bottom navigation и safe-area.

### Mentalix interpretation

- Использовать реальные `api.analytics.get`, check-ins, rituals и ascezas.
- Сохранить честный порог данных и текущие caveat-формулировки; не создавать причинные выводы.
- Не переносить HealthKit, daylight, mindful minutes или иные отсутствующие источники.
- Period selector ограничить реально поддержанными периодами; `Years` не показывать без данных/API.
- Empty states должны объяснять, какое существующее действие создаст данные.

## 6. Не переносим из референсов

- брендинг, тексты, английский язык и типографику Stoic;
- premium/paywall механику, цены и free trial;
- HealthKit и отсутствующие источники данных;
- sharing achievements;
- новые категории/темы, которых нет в данных Mentalix;
- новые backend endpoints, router, глобальный state manager;
- document-level touch handlers;
- фиолетовую палитру, градиенты и буквальные Stoic-иллюстрации.

## 7. Acceptance gate для текущего UI Lab #526

- Маршрут Preview-only: `?ui_lab=library`.
- На 390 × 844 видны header, первый content rail и начало «Коллекций»; bottom navigation ничего не перекрывает.
- На 375 × 812 и 320 × 568 нет clipping, горизонтального overflow страницы и обрезанного текста.
- Rail прокручивается пальцем и snap-ится; следующий элемент виден до свайпа.
- Активные карточки открывают соответствующий demo/detail state; «Практикумы» не активны.
- Проверены loading/error/empty/search-empty/web-restriction состояния.
- Используются Onest/Manrope и токены Mentalix; глобальные production-стили не изменены.
- `npm run check:core`, `npm run ux:check`, targeted UI Lab checker и `git diff --check` проходят.
- После локального self-check нужен owner gate на canonical `mentalix-preview`; только затем разрешён отдельный production-integration diff.

## 8. Rollback и scope lock

- Текущий этап меняет только UI Lab и этот reference contract.
- Production Library, API, backend, навигация и Vercel-конфигурация не меняются.
- Rollback — удалить UI Lab route/components/tests и этот документ одним revert PR; пользовательские данные не затрагиваются.
