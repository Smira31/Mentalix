# Mentalix — manual QA pass

**Дата:** 20.09.2026  
**Среда:** Telegram Mini App в production; дополнительно web/PWA, если маршрут доступен в текущей сборке.  
**Область:** актуальный `src/` из `main` репозитория `Smira31/Mentalix`; контракты API сверены с `Smira31/mentalix-bot` (`backend/` и `bot/`).  
**Цель:** пройти приложение как обычный пользователь и зафиксировать только новые воспроизводимые дефекты.

> **Правило для этого прохода.** Не репортить повторно пункты из раздела «Известные баги». Если известный дефект изменился, ухудшился или проявился в другом потоке, приложить ссылку на исходный пункт и описать именно регрессию.

## Известные баги — не репортить повторно

Следующие симптомы уже зафиксированы в `TASKS.md`/`CHANGES.md` или в связанном PR-контексте. Во время прохода их нужно только проверить для понимания границ регрессии, но не создавать новый баг с тем же симптомом.

- [ ] **Check-in: дублирующаяся стрелка/элемент возврата.** Если на одном экране видны две стрелки назад или одновременно видны Telegram BackButton и внутренняя стрелка, это уже известный визуальный дефект. Не заводить повторный баг без нового контекста или нового устройства.
- [ ] **Today: дублирующая верхняя шапка.** В открытом PR #704 зафиксирована лишняя верхняя строка на экране «Сегодня»; повторно не репортить именно дублирование header.
- [ ] **Today: лишняя кнопка создания собственных практик.** В том же открытом PR #704 зафиксирована кнопка «Создать свои практики» в панели «твои практики»; не заводить дубликат по её наличию.
- [ ] **Шкалы/чипы check-in: серый градиент.** Серый градиент или несоответствующая плоской поверхности подложка на шкалах/чипах уже отмечены как известный визуальный симптом.
- [ ] **Вечерний check-in «Чем горжусь»: белая рамка поля.** Белая или слишком контрастная рамка вокруг этого поля известна. Повторно не репортить только её наличие.
- [ ] **Счётчик «X из N».** Если старый счётчик шага всё ещё отображается там, где по текущему UX его должны были убрать, это уже известный симптом.
- [ ] **Малые экраны и fixed action bar.** На узких viewport уже известны отдельные проблемы с доступным пространством, клавиатурой и позиционированием action group в fullscreen-потоках. Новый дефект — только если он отличается от зафиксированного поведения или ломает другой поток.
- [ ] **PWA/Safari splash при запуске с иконки.** Зависание splash/лабиринта при старте standalone PWA связано с открытым Issue #647; не заводить дубликат без нового шага воспроизведения или нового браузера.
- [ ] **Ограничения связанных web-аккаунтов.** В web/PWA чувствительный export, удаление и часть owner-scoped операций могут быть недоступны без проверенной Telegram-сессии. Это ожидаемое ограничение текущего контракта, а не баг.
- [ ] **Синхронизация черновика.** Незавершённый check-in хранится локально на текущем устройстве и не обещает cloud backup, offline queue или conflict resolution. Не репортить отсутствие автоматического переноса черновика как дефект.
- [ ] **Серия.** Streak рассчитывается по доступной 90-дневной истории завершённых check-in; пропущенные дни не восстанавливаются и серия не редактируется вручную. Это текущее ограничение реализации.
- [ ] **Открытые product/preview-only issues.** Preview-only задачи и идеи из открытых Issues не считать дефектами production, пока соответствующий пользовательский экран не заявляет такую возможность.

## 2. Вход, онбординг и защитные гейты

### 2.1 Telegram авторизация и первый запуск

- [ ] Открыть приложение из Telegram с новым или очищенным профилем.
- [ ] Проверить состояние загрузки и отсутствие белого/пустого экрана при медленном соединении.
- [ ] Пройти онбординг по каждому экрану: продолжить, вернуться назад системной кнопкой Telegram и снова продолжить.
- [ ] Оставить обязательное поле онбординга пустым и проверить валидацию, disabled-состояние CTA и понятное сообщение об ошибке.
- [ ] Ввести обычный текст, длинный текст, emoji и пробелы по краям; проверить сохранение только валидного значения.
- [ ] Закрыть Mini App на середине онбординга и открыть снова; проверить, сохраняется ли только предусмотренный прогресс и не перескакивает ли пользователь через незавершённый шаг.
- [ ] Завершить онбординг и убедиться, что повторный запуск не показывает его снова без причины.
- [ ] Проверить Telegram back, внутреннюю кнопку назад и закрытие Mini App на первом и последнем шаге.

### 2.2 Web/PWA auth и связанный аккаунт

- [ ] Открыть web/PWA без сессии; проверить экран email/Telegram auth.
- [ ] Отправить пустой email, невалидный email, email с пробелами и валидный email.
- [ ] Ввести неверный, просроченный и повторно запрошенный код; проверить сообщения и возможность изменить email.
- [ ] Обновить страницу на шаге ввода кода; проверить, не возникает ли ложная авторизация или потеря понятного состояния.
- [ ] Проверить переход «через Telegram», успешное возвращение и отказ/отмену авторизации.
- [ ] Проверить linking web account из Telegram: повторный link, уже связанный аккаунт и отказ backend.
- [ ] После входа сравнить доступность профиля и обычных записей с Telegram; убедиться, что чувствительные действия корректно ограничены.

### 2.3 Privacy notice, lock и mood gate

- [ ] Открыть privacy notice из предусмотренного entry point; раскрыть каждый блок и проверить возврат.
- [ ] Прочитать/подтвердить privacy notice, затем повторно открыть приложение и проверить отсутствие неожиданного повторного гейта.
- [ ] В настройках создать PIN, ошибиться при подтверждении, отменить настройку и снова открыть экран.
- [ ] Заблокировать приложение; проверить неверный PIN, верный PIN, повторный lock и поведение после background/foreground.
- [ ] Если доступен Face ID/Touch ID, проверить отказ биометрии и fallback на PIN.
- [ ] При запуске с включённым mood gate выбрать каждый вариант, пропустить, нажать назад и пройти gate повторно.
- [ ] Проверить, что mood gate не перекрывает Telegram/system controls и не оставляет приложение в заблокированном состоянии после завершения.

- [ ] Переключить коллекции/темы; проверить active state, горизонтальную прокрутку и отсутствие обрезки карточек.

Для каждого флоу ниже пройти старт, каждый шаг, Back/закрытие, повторный вход, успешное завершение и возврат в исходную вкладку.

- [ ] **Одно завершение (`FinishFlow`).** Ввести задачу, пройти timer/action/review, проверить досрочный выход, завершение и повторный вход.

- [ ] **Дыхание (`Breathing`).** Запустить цикл, проверить timer/анимацию, остановить, завершить, выйти досрочно и открыть повторно.

## Scope reconciliation: код против контекста и документации

На момент подготовки файла GitHub показывает PR #694, #690, #689 и docs-PR #680–687 как **merged**. Их функциональность обнаружена в текущем `main` и поэтому отражена в чек-листе: сокращённый morning check-in и streak, единый check-in для PWA/Telegram, Guided Self-Discovery UX и gated Meditation/актуализированные UX-аудиты.
