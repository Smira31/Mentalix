2. Product hypothesis: Mentalix inside Telegram

Рабочая формула:

Mentalix = Personal Action System inside Telegram

Mentalix не должен позиционироваться как:

• ещё один AI-психолог;
• ещё один habit tracker;
• ещё один productivity app.

Основной цикл ценности:

понять себя → выбрать направление → сделать следующий шаг → удержать систему → увидеть закономерности

Это не отменяет уже зафиксированный в PRODUCT.md daily loop, а уточняет его Telegram-native форму.

Как существующие функции складываются в систему

• Check-in → где я сейчас;
• Следопыт → что со мной происходит;
• Собеседник → разобраться;
• Наставник → принять решение;
• Ритуалы → что делать регулярно;
• Аскезы → что не делать;
• Следующий шаг → что сделать сейчас;
• Тренды → увидеть закономерности;
• Библиотека → понять, почему это работает;
• Bot → вернуть пользователя, когда он выпал.

3. Telegram architecture

Mentalix должен проектироваться как одна система с двумя равноправными интерфейсами.

BOT

Bot отвечает за:

• диалог;
• быстрый check-in;
• напоминания;
• голосовые сообщения;
• возвращение пользователя;
• инициирование действий;
• утренний контакт;
• сценарий выпадения из ритма;
• завершение дня;
• недельный разбор;
• contextual deep links в Mini App.

MINI APP

Mini App отвечает за:

• визуальную систему;
• Today;
• прогресс;
• ритуалы;
• аскезы;
• состояние;
• тренды;
• стратегическую картину;
• библиотеку;
• глубокие разборы;
• историю пользователя.

Целевой переход:

Bot → конкретное действие в Mini App → completion → следующий шаг / дальнейший контакт Bot

Bot и Mini App не проектируются как два отдельных продукта.

4. Что подтверждает существующая документация

Новый Telegram research усиливает уже принятые решения Mentalix:

3. PRODUCT.md: не расширять поверхность продукта крупными функциями до подтверждения core loop.
4. ROADMAP.md: P1 — подтвердить ежедневный цикл check-in → следующий шаг → практика → вечерний разбор → продолжение завтра.

6. Уже реализованные идеи из старого competitive analysis не следует открывать повторно как новые задачи.

6. MENTALIX_TELEGRAM_UX_V1

Layer 1 — Telegram-витрина

Нужно оценить как единую product storefront:

• аватар;
• имя;
• username;
• description;
• /start;
• Main Mini App;
• Launch App;
• preview/demo media;
• loading screen;
• Telegram profile.

Обсидиановый персонаж Mentalix — часть общей visual identity, а не только аватар бота.

Цель слоя: новый пользователь до первого сложного действия понимает что такое Mentalix, зачем он ему и что нажать сейчас.

Layer 2 — Telegram Assistant

Сценарии для проектирования:

• утро;
• быстрый check-in;
• напоминание;
• пропущенный ритуал;
• выпадение на несколько дней;
• сообщение о проблеме;
• voice message;
• следующий шаг;
• завершение дня;
• недельный разбор;
• возврат в Mini App.

Стандарт описания сценария:

trigger → сообщение → CTA → deep link → экран Mini App → действие → completion → следующий контакт

Layer 3 — Mini App Core Loop

Целевой маршрут:

Onboarding → Today → одно главное действие → выполнение → feedback/completion → следующий шаг

Главный принцип:

одна сессия ≈ одно понятное действие

Не заставлять пользователя изучать всю систему до получения первой пользы.

7. Telegram UX principles

1. Одна понятная ценность вместо каталога функций.
2. Минимальный порог входа.
3. Telegram-native onboarding.
4. Возвращение пользователя через диалог.
5. Одно главное действие за сессию.
6. Contextual deep links.
7. Bot и Mini App работают как единая система.
8. Today отвечает на вопрос: «Что мне сделать сейчас?»
9. AI не только разговаривает — AI переводит понимание в действие.
10. Не показывать пользователю всю сложность Mentalix сразу.
11. Retention строится вокруг полезного возвращения, а не бессмысленных уведомлений.
12. Telegram profile/Main Mini App рассматривается как внутренняя storefront-page продукта.

8. Сопоставление нового research со старым

Что подтвердилось

• Один следующий шаг — правильный центр продукта.
• Check-in должен вести дальше, а не становиться самоцелью.
• AI должен завершать разговор переходом к проверяемому действию, когда это уместно.
• Retention лучше строить через продолжение незавершённого пользовательского контекста.
• Новые идеи должны «утолщать» существующие треки, а не создавать новые вкладки.

Что нужно изменить / проверить

• Проверить, достаточно ли ясно Telegram-профиль объясняет продукт.
• Проверить /start как первый продуктовый экран, а не техническое приветствие.
• Формализовать handoff Bot ↔ Mini App через deep links.
• Проверить, отвечает ли Today в каждом состоянии на вопрос «что сделать сейчас?».
• Связать уведомления с конкретным продолжением действия, а не общим призывом вернуться.

Что уже реализовано и не должно дублироваться

• базовый core loop существует;
• Telegram fullscreen/safe areas уже проходили живую проверку;
• ритуалы и аскезы существуют;
• check-in существует;
• AI-персоны и переходы к ним существуют;
• Тренды/аналитика существуют;
• competitive ideas из ROADMAP.md, отмеченные там как закрытые, не открывать повторно;
• onboarding уже имеет отдельную GitHub Issue #117 — Telegram UX criteria следует добавить туда, а не создавать дубликат.

Что требует улучшения

• первый запуск и объяснение ценности;
• Today как one-action surface;
• Telegram storefront;
• Bot ↔ Mini App handoff;
• return flows;
• completion → next step.

Новые идеи, не являющиеся автоматическим MVP

• полноценный voice-to-action flow;
• стратегическая карта по сферам жизни;
• расширенная автоматическая приоритизация AI;
• сложные pattern recommendations.

9. Приоритет решений

P0 — до качественного первого релиза

• Telegram-витрина и первый запуск;
• Telegram-native onboarding (в рамках существующей #117);
• понятный Today / One Action;
• базовая архитектура Bot ↔ Mini App и contextual deep links;
• минимум один завершённый return flow: сообщение → конкретный экран → completion;
• проверка всего пути на реальном iPhone в Telegram.

P1 — после стабилизации core loop

• системные reminder/return flows;
• сценарий выпадения из ритма;
• day completion;
• weekly review delivery;
• расширение Telegram-native retention без новых основных экранов.

P2 / V2–V3

• voice-to-action;
• стратегическая карта жизни;
• AI prioritization по сферам;
• более сложная cross-feature аналитика.

Research

• ручной UX review @munai_app_bot;
• глубокий проход Kora, WantToPay, Плати по миру, Wise Insights, RebootMe, Habit Tracker, PsychologyAI, Анна, Mira;
• скриншоты onboarding/home/CTA/paywall/return/deep-link сценариев;
• выбор пяти strongest references для следующего product review.

10. Правило принятия решений

Новая конкурентная идея попадает в разработку только если одновременно выполняются условия:

1. усиливает текущий core loop;
2. сокращает путь до полезного действия или повышает вероятность возвращения;
3. не требует новой основной вкладки без отдельного продуктового решения;
4. имеет понятный acceptance criterion;
5. приоритет выше, чем стоимость переключения и поддержки.

Если идея интересная, но эти условия не выполнены — оставить её в Research/V2/V3.
