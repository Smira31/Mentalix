# MXL-DEC-025 — Pattern insights: execution plan

## Цель

Проверить, готовы ли пользователи возвращаться ради осторожных pattern
insights на основе накопленной истории.

## Зависимости

MXL-JOURNAL-PERSISTENCE-001, MXL-JOURNAL-HISTORY-001, корректная модель
даты/timezone, provenance-слой.

## Ограничения

- Никаких диагнозов.
- Никаких причинных заявлений («X вызывает Y»).
- Никаких выводов по малой выборке (см. sample-size guard ниже).

## Дизайн прототипа

1. **Sample-size guard:** минимальный порог записей (N уточняется в
   ходе прототипирования, стартовая гипотеза — не меньше 7 релевантных
   точек данных) — ниже порога insight не показывается вообще, вместо
   заглушки.
2. **Provenance:** каждый insight ссылается на конкретные записи/даты,
   на основе которых сделан — пользователь может провалиться и увидеть
   исходные данные.
3. **2–3 типа observations** (примеры, не финал):
   - частотные паттерны по времени суток/дню недели;
   - совпадения тегов/тем без причинной интерпретации;
   - изменение частоты определённого типа записи за период.

## Метод измерения

- Показать прототип небольшой группе пользователей.
- Замерить perceived usefulness (короткий опрос после показа).
- Замерить return intent (готовность зайти снова ради нового insight).

## Что НЕ входит

- Продакшен-реализация insight-движка.
- ML/статистические модели — эвристики достаточно для теста гипотезы.
- Персонализация формулировок под тон пользователя.

## Acceptance criteria

- [ ] Sample-size guards определены и задокументированы.
- [ ] Provenance-механизм работает в прототипе.
- [ ] 2–3 типа observations реализованы.
- [ ] Perceived usefulness и return intent измерены.
