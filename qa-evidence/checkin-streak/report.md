# Стабильность финала чек-ина и экрана серии (fix-checkin-layout)

Прогон Chromium (Playwright), web-контейнер Base44, ветка `fix-checkin-layout`
(`f3dc032` + правка контракта дней ряда). Вьюпорты задачи — 430×932
(iPhone 15 Pro Max) и 360×640.

## Что изменилось после f3dc032

1. **Композиция экрана серии.** Вместо ростка — цветок из пяти отдельных
   лепестков (пустой центр), заголовок «Серия: N дней», одна строка пояснения
   к иллюстрации, ряд дней длиной серии (до недели), сцена центрируется по
   свободной высоте. С финалом чек-ина общими остаются оболочка, полоса шапки
   `.mx-finale-header-slot` и главная кнопка; прежние полосы финала (плашка
   даты, блок отзывов) в серию не переходят.
2. **Контракт дней ряда** (`src/lib/streakCelebration.js`) — см. раздел ниже.

## Контракт streak/checkins: неизвестную дату нельзя отмечать

**Было.** `buildStreakDays` любую дату без записи помечал `done` (галочка),
и только в частном случае `freezeUsed && singleHole` — `gap` (тёмный кружок,
то есть пропуск).

**Почему это неверно.** Двух причин достаточно по отдельности:

- серия мягкая: день закрывает любая завершённая активность (чек-ин, журнал,
  ритуал, аскеза, «Настроение»), а ряд строится по истории чек-инов, поэтому
  отсутствие записи не доказывает, что день выполнен;
- заморозку нельзя приписать конкретному дню: сервер отдаёт только факт
  заморозки недели, без её даты (`PROJECT_STATE.md`, `docs/TASK_INDEX.md`),
  поэтому одиночная дыра в истории — тоже «неизвестно», а не «пропущено».

**Стало.** Состояние дня берётся только из записи этого дня: `done` —
день есть в истории чек-инов, `today` — сегодня (огонёк), `unknown` — записи
нет (нейтральный кружок без значка). Состояния `gap`/`missed` из ряда удалены
вместе с параметром `freezeUsed`; вызовы в `CheckIn.jsx` (утренний и вечерний
финал) обновлены, ряд дней больше не принимает факт заморозки.

**Целевые проверки** (`tests/unit/streak-celebration.test.mjs`):

- «ряд дней: день без записи — неизвестный, не выполненный и не пропущенный»;
- «неполная история: выполнен только день с записью, остальные — неизвестные»
  (в том числе обрезанная история с одной записью и записи вне ряда);
- «заморозка не приписывается дню: ряд не решает за сервер» (с фактом
  заморозки и без него ряд одинаков; в модуле нет ни параметра заморозки,
  ни состояния пропуска);
- «ряд дней: значок стоит только у сегодня и у подтверждённого дня».

**Замер в браузере** (тот же spec, новые метрики `doneDays`/`unknownDays`):
в реальном переходе — `streakDays 7 / doneDays 2 / unknownDays 4 / gapDays 0`
на обоих вьюпортах (2 дня с записями, остальные неизвестны, пропусков нет);
в демо-ссылке без истории галочек нет вовсе — `doneDays 0`, прошедшие дни
`unknown`, `gapDays 0`.

### Настоящий переход (тест 9)

Идёт по реальному пути приложения: утренний чек-ин, текст, «Завершить»,
оценка «Помогло?», «Сохранить и выйти» и появление экрана серии. API
подменяется только внутри теста: до сохранения серия 8 дней и сегодня не
активен, после — 9 и активен. Экран серии действительно открывается
(`Серия: 9 дней`), цветок показывает 4 светлых лепестка (9-й день в текущем
круге из пяти), ряд — 7 элементов: 2 дня подтверждены записями, 4 неизвестны,
сегодня — огонёк, пропусков нет.

## Исправление 3 px и общий шелл

У утреннего финала шапку задавала строка контролов
`.mx-demo-checkin__header` (`var(--mx-header-control) + 12px` = 55 px), а
вечерний финал и экран серии использовали `FULLSCREEN_HEADER_SLOT_CLASS`
(52 px). Из-за разницы герой серии начинался на 3 px выше иллюстрации
финала — при переходе экран прыгал.

Теперь финал и серия используют один класс `.mx-finale-header-slot`
(`min-height: calc(var(--mx-header-control) + 12px)`, тот же `padding-inline`,
`flex: none`): полоса шапки замерена как 0 / 55 px на обоих вьюпортах, а
главная кнопка стоит на одной линии — 838 px на 430×932 и 546 px на 360×640.

## Fullscreen: что тест стабилизирует, а что нет

- В тесте итоговое состояние платформы сообщается штатным событием SDK —
  `Telegram.WebView.receiveEvent('fullscreen_changed', { is_fullscreen: false })`
  (`answerFullscreen()`), то есть приложение проходит настоящий путь SDK,
  а не подмену React-состояния.
- Зачем: пока Telegram не подтвердил fullscreen, приложение резервирует сверху
  56 px под контролы и снимает запас по таймауту
  (MXL-FULLSCREEN-SURFACE-RACE-001). Без ответа платформы финал измерялся бы
  с запасом, а серия — уже без него, и тест ловил бы гонку таймаута вместо
  верстки. С ответом `is_fullscreen: false` запас равен нулю на обоих экранах
  (`padding-top: 0px`), условия теста стабильны и воспроизводимы.
- **Ограничение, которое тест не покрывает:** исчезновение резерва 56 px
  в реальном Telegram (когда `fullscreen_changed` приходит с задержкой или не
  приходит вовсе) не проверено. Это поведение таймаута в живом клиенте, его
  нельзя воспроизвести в Chromium.

## Ограничения проверки

- Прогон только Chromium/Playwright; клавиатура имитируется подменой
  `visualViewport.height` при неизменном `window.innerHeight` (как ведут себя
  iOS/Telegram), аппаратная клавиатура не задействована.
- Полный `check:core` и полный `ux:check` — CI (job «Playwright Chromium
  smoke»), локально прогонялся только целевой файл, набор которого изменён.
- Кадры в этой папке сняты до правки контракта дней и показывают прежнее
  состояние дня без записи (галочку); новые кадры по указанию владельца не
  добавлялись. Текущее состояние дня подтверждено замерами `doneDays` /
  `unknownDays` в целевом прогоне и unit-тестами выше.
- Экран серии по демо-ссылке не открывается в оболочке превью Base44: оболочка
  подменяет параметры адреса своими (`location.search` = `_preview_token…`),
  поэтому экран проверялся целевым Playwright-набором, а для ручного просмотра
  доступен по демо-ссылке PR-превью (сборка PR идёт с `VITE_LOCAL_PREVIEW=true`).
- **iPhone и Telegram — NOT RUN.** Проверка на реальном устройстве и в клиенте
  Telegram остаётся за владельцем; merge и production deploy не выполнялись.

## Прочие изменения этой ветки

1. `StreakCelebration.jsx` / `.css`: своя компактная сетка серии с
   фиксированными полосами (иллюстрация 148 px, на коротком экране 112 px;
   заголовок, пояснение, ряд дней) и центрированием сцены по свободной высоте
   (прежний верхний отступ `max(16px, 33dvh − …)` снят).
2. `StreakGlyphs.css`: у незажжённых лепестков появился тонкий контур
   (`rgba(243,243,243,0.22)`, 0.75 px). Без него при одном светлом лепестке
   остальные четыре неразличимы и цветок читается как одиночный росток.
3. `stable` включён на всех экранах без полей ввода: утренний и вечерний финал
   (`CheckIn.jsx`), экран серии (`StreakCelebration.jsx`). Тест доказывает это
   замером: высота шелла равна `window.innerHeight` и при открытой, и при
   закрытой клавиатуре.
4. Контракт дней ряда: `src/lib/streakCelebration.js`, вызовы в
   `src/screens/CheckIn.jsx`, тесты — см. раздел выше.
5. Временная папка `public/__qa_tmp/` (скриншоты и html-листы промежуточных
   замеров) удалена из репозитория — в ветке остаются только кадры
   `qa-evidence/checkin-streak/`.
