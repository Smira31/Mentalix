### Движок курсов и сохранность данных

Раньше HeroJourneyMap напрямую импортировал HERO_JOURNEY_COURSE/TRIALS/CHAPTERS и функции из heroJourney: содержание «Пути героя» было зашито в один экран. Теперь экран получает объект course; courseContent и CourseContext предоставляют карту, главы, шаги и финал. Название HeroJourneyMap оставлено для совместимости, но данные выбранного курса больше не ограничены «Путём героя».

**Как добавить курс:** создать `src/data/courses/<id>.js` с default-объектом: уникальный `id`, `title`, `label`, `description`, `image`, `chapters`, `steps`, при необходимости `subtitle` и `finale`. Глава содержит `key`, `roman`, `title`, `subtitle`, `trialIds`; шаг — стабильный `id`, последовательный `number`, `title`, `subtitle`, `description`, `prompt`, `action` и необязательные поля существующего шага. `import.meta.glob` подхватит файл автоматически: менять реестр или UI не нужно. Для обычного курса не задавать demoOnly. Один курс — полная ширина; два/три — общая карусель; «Все курсы →» появляется при числе курсов >3.

**Прогресс:** для hero-journey прежние локальные ключи точно сохранены: `mx-hero-journey-progress:<userId>` и `mx-hero-journey-draft:<userId>:<stepId>`. В CloudStorage scoped-ключ по-прежнему заменяет двоеточия на подчёркивания; миграция старого облачного ключа остаётся только для hero-journey. У других курсов прогресс и черновики изолированы по userId + courseId. Серверного API прогресса этот движок не вызывает; backend/API не менялись. Unit-тест проверяет точные старые ключи и изоляцию. UX прошёл реальный шаг, проверил completed/reflections в старом ключе, перезагрузил страницу и увидел «Шаг 2 из 16» / «Пройдено 1 из 16». Реальные Telegram-аккаунты и перенос CloudStorage между устройствами автоматически не проверялись.

## Источник статей

Выбран **статический `src/data/articles.js` (`ARTICLES`)**. В main действующая v2 уже показывала именно эти восемь полных материалов, тогда как параллельный API-каталог загружался для старого представления (в демо `/articles` даже возвращает пустой массив). Для этой задачи надёжнее сохранить опубликованные полные тексты и хранить вопросы рядом с ними.

Главная, шторка и читалка используют один `libraryArticles`; совместимый `libraryDataCache.js` возвращает тот же массив для старых потребителей. API не выбирает второй набор и устаревшие sessionStorage-снимки не подменяют контент. **Запасной вариант при недоступном API — тот же встроенный каталог:** статьи сразу доступны без сети, ожидания и падения, без смешивания двух версий. API-метод сохранён для совместимости, но продуктовая Библиотека его не вызывает. Публикация новых статей по-прежнему через коммит/релиз.
