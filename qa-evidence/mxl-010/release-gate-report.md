# MXL-010 — Frontend Release Gate Report

**Проект:** [`Smira31/Mentalix`](https://github.com/Smira31/Mentalix)  
**Scope:** только frontend; `Smira31/mentalix-bot` не изменялся.  
**Проверяемая база:** `origin/main` at `29f156180941d5dc326f3e965124c42c2f6e1f3d` (checkout/fetch выполнены перед тестированием).  
**QA branch:** `manus/release-e2e-gate`, создана от `origin/main` только для QA-артефактов.  
**Дата проверки:** 2026-08-29.  
**Итоговый gate:** **BLOCKED**.

## Решение

Локальный frontend quality gate и детерминированный UX smoke проходят. Полный пользовательский E2E-цикл MXL-010 доказать нельзя: web fallback останавливается на реальном OTP/email авторизационном шаге, Preview PR #312 из текущего sandbox-сеанса редиректит на Vercel login, а Telegram/iPhone runtime и backend contract access не предоставлены. Это **не доказательство frontend-дефекта** и не должно быть преобразовано в PASS документацией или fixture-тестом.

Открытые PR сверены с GitHub. Из доступных открытых PR только #312 меняет frontend-поведение авторизации; его Preview metadata содержит deployment, но runtime доступ заблокирован. PR #302 также имеет исторический Preview URL в комментарии, однако owner не указал его как Preview для текущей проверки, и deployment context не является актуальным доказательством для `origin/main`. Vercel status для некоторых PR сообщает rate limit `api-deployments-free-per-day`; это классифицируется как **средовая проблема**, а не как frontend regression.

## Merge order and owner actions

Do not merge any PR as “MXL-010 E2E verified” based on this run. Keep the QA branch separate from `main`; if the owner wants the report committed, merge only the QA-artifact PR after reviewing that it contains no source/backend changes. PR #312 should be Preview-tested after the owner provides an accessible deployment/session, then compared against the same origin/main fixture baseline. Documentation-only PRs should not be used as substitutes for that runtime gate.

The owner must provide a non-production test account or deterministic backend test mode that can complete OTP/auth, morning and evening check-ins, AI dialogue, handoff, day rollover, persistence, reload and duplicate-completion audit without real private data. The owner must also run the manual Telegram Mini App gate on a real iPhone for fullscreen, safe-area insets, keyboard/input, long AI answer scrolling and bottom navigation at 320x568, 390x844 and the available wide iPhone size. Capture one screenshot or screen recording per critical transition, redact user data, record commit/Preview URL and account mode, and attach backend request/response IDs without tokens or private content.

After those prerequisites are available, rerun all ten steps in order, mark each row PASS/FAIL/BLOCKED, and only then change the gate to PASS or FAIL. Any confirmed frontend regression should be fixed minimally in a separate commit on this QA branch; backend-contract or environment findings must become separate issues/PRs.
