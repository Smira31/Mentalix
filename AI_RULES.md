# Mentalix — технические инварианты для ИИ

> Этот файл сохраняет только технические правила, которые легко нарушить при изменении кода. Общий контракт для всех агентов находится в [`AGENTS.md`](AGENTS.md), а минимальный маршрут по документации — в [`PROJECT_BRIEF.md`](PROJECT_BRIEF.md). Не читайте этот файл для координации, документации или планирования без frontend-кода.

## Когда он нужен

Открывайте этот файл только перед изменением React-компонентов, platform layer, таймеров, состояния, Tailwind-классов или общих hooks. Для продуктовой, UI- или backend-зависимой задачи сначала следуйте маршруту из `PROJECT_BRIEF.md`.

## Инварианты кода

| Область          | Правило                                                                                                                                                                       | Почему это важно                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Платформа        | Единственная точка входа в Telegram SDK — `src/platform/`. Прямой импорт `@twa-dev/sdk` за пределами этого каталога запрещён.                                                 | Локальные обёртки расходятся по haptic/error/success поведению.                                     |
| Время            | Таймер рассчитывается от временной отметки (`Date.now()`), не суммированием тиков `setInterval`. Пользовательское участие ставится на паузу при скрытом экране.               | Telegram WebView ограничивает таймеры в фоне; заблокированный экран не должен засчитывать практику. |
| Побочные эффекты | В `setState(previous => next)` допускается только вычисление нового состояния. API, другие setters, `clearInterval` и записи выносятся в отдельный effect с `useRef`-защитой. | В StrictMode updater может вызываться повторно, создавая дубли записей.                             |
| Общие hooks      | Экран импортирует общий hook непосредственно, а не копирует его значения или логику под новым именем.                                                                         | Локальная копия незаметно расходится с общим контрактом.                                            |
| Текст UI         | Используйте `text-cream`, `text-muted` и `text-faint`, а не статичную прозрачность текста.                                                                                    | Прозрачность часто не обеспечивает требуемый контраст.                                              |
| Tailwind         | Не конструируйте имена Tailwind-классов из переменных во время выполнения.                                                                                                    | Tailwind включает в production только классы, найденные в исходнике буквально.                      |
| Документация     | Значения токенов живут только в `DESIGN_SYSTEM.md`; остальные файлы ссылаются на него, не копируя численные значения.                                                         | Копии быстрее расходятся с кодом, чем их успевают синхронизировать.                                 |

## Тестовый цикл и честность результата

Один тестовый цикл охватывает не более двух пользовательских функций одной проблемы. Для каждой функции заранее укажите наблюдаемый результат. Критическое исправление, найденное в этом же цикле, не считается новой функцией.

Не заявляйте «готово», если пройдена только сборка. Не заявляйте, что backend поддерживает сценарий, если приватный backend не был проверен. Не называйте рекомендацию решением владельца. В Pull Request перечисляйте выполненные и невыполненные проверки, а также их ограничения.
