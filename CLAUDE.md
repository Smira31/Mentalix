# Правила для Claude Code — Mentalix

- После КАЖДОЙ выполненной задачи обязательно обнови CHANGES.md и статус в TASKS.md — по правилу AI_RULES.md §6.1. Делай это в том же диффе/коммите, не отдельным шагом.
- Workflow: branch → staged diff → явное подтверждение владельца → commit/push → squash-merge PR → удали ветку (remote + local).
- Перед мёржем или сменой статуса задачи из TASKS.md — сначала сверь фактическое состояние (git log, ветки, PR) с описанием в файле. TASKS.md часто отстаёт от реального git-состояния.
- Перед новой крупной фичей — предложи владельцу skill pre-mortem (~/.claude/skills/pre-mortem/SKILL.md).
- Продуктовые решения (PRODUCT_DECISIONS.md) меняет только владелец, датированным блоком поверх старого текста — историю не стирать.
- Технические решения в объёме задачи принимай сам, кратко объясняя выбор.
- Никогда не пуш в main напрямую, минуя branch → diff → PR.
- Не использовать git update-ref для переключения/синхронизации веток без checkout — это может оставить рабочее дерево не в актуальном состоянии, даже когда ссылка ветки верна. Использовать git checkout / git switch.
- Отвечай кратко, без пересказа очевидного.
