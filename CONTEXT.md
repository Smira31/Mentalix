# Контекст проекта Mentalix — legacy / historical context

> Этот файл сохранён как исторический контекст и шаблон работы из ранней
> стадии проекта. Он не является источником правды. При конфликте с кодом
> или актуальными нормативными документами следует использовать код и
> документы из списка ниже.

**Проект:** Mentalix — Telegram Mini App (система ритуалов, аскез, чек-инов).
Прод: https://mentalix.vercel.app

## Стек и репозитории

**Фронт — `github.com/Smira31/Mentalix` (публичный).**
React + Vite + Tailwind. Деплой Vercel, автосборка при пуше в `main`.

**Бэкенд — `mentalix-bot` (приватный).**
FastAPI + SQLAlchemy + aiogram. Деплой Railway.
Папки: `backend/` (API), `bot/` (Telegram-бот).

> ⚠️ **Бэкенд приватный — модель его не увидит.**
> Если задача касается API, моделей или бота, файлы надо прислать вручную.
> Обычно достаточно: `models.py`, нужный роутер, схемы Pydantic.
> Фронт — публичный, его можно забрать из репозитория.

## Дизайн

Стиль **stoic.** — плоский тёмный минимализм.
Символ — лабиринт, заполняющийся золотом по прогрессу.

> Шрифт, палитра и токены здесь намеренно не дублируются.
> Единственный источник — [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md).

**Тон:** на «ты», коротко, без «успешного успеха».
**Аудитория:** 25–35.

## Правила экономного общения

1. Новый чат на каждую задачу. Длинный чат = всё перечитывается заново.
2. Не пересылать то, что есть в публичном репозитории — оно читается само.
3. Видео и большие PDF — только когда без них никак. Это самое дорогое.
4. Скриншот вместо описания — хорошо. Скриншот + подпись «что не так» — лучше.
5. Файлы поштучно, если меняется 1–3 файла: меньше вывода, меньше шансов
   ошибиться при загрузке на GitHub.
6. Складывать несколько мелких правок в один запрос вместо пяти подряд.
7. Когда задача закрыта — закрывать чат, а не продолжать в нём следующую.
8. После крупной задачи — обновить `CHANGES.md` и `TASKS.md`.
   Иначе контекст разойдётся с кодом.

## Правило загрузки на GitHub (чтобы не терять файлы)

- Тащишь папку `src` — стой в **КОРНЕ** репозитория.
- Тащишь голые файлы (`App.jsx`, `api.js`) — сначала **ЗАЙДИ** в нужную папку.
- После коммита проверь: сколько файлов изменилось. Ноль — значит не доехало.
- Vercel собирает при пуше в `main`. Билд упал — смотри логи в Vercel,
  а не гадай по коду.
