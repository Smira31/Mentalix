## Подготовлено 09.08.2026 — Инструменты форматирования и линтинга фронтенда

- Сверена фактическая структура репозитория перед началом: `package.json`, `src/`, `eslint.config.js` лежат в корне `frontend-deploy` — отдельной вложенной папки `frontend/` нет.
- По аналогии с бэкендом (`black`/`autoflake`/`pylint`) добавлены `.prettierrc`, `.editorconfig`, `.prettierignore`; в `eslint.config.js` подключены `eslint-plugin-prettier`/`eslint-config-prettier` (плагин зарегистрирован ради интеграции с `lint:fix`, само правило `prettier/prettier` выключено — см. ниже почему); добавлен скрипт `"format": "prettier --write ."`.
- `.prettierrc` не скопирован от бэкенда буквально: `semi` выставлен в `false` (не `true`, как в `mentalix-bot`), потому что в этом фронтенде точки с запятой почти нигде не используются (проверено — 2 файла из 76); добавлен `"endOfLine": "auto"`, иначе Prettier требует LF, а рабочие копии на Windows в CRLF, и это давало 18000+ ложных предупреждений «Delete `␍`» на ровном месте.
- **Важное расхождение, зафиксировано, не решалось молча:** в кодовой базе есть намеренный стиль — часть выражений (деструктуризации `useState`, JSX-условия) разбита на несколько строк по одному идентификатору. Prettier так не умеет и при `--write` схлопывает это в одну строку; пробный прогон `prettier --write .` по всему репозиторию дал diff на ~16 000 строк почти во всех `src/**` файлах. Такой diff поверх ~10 параллельно открытых веток — риск конфликтов при каждом будущем мёрдже. Решение (наименьший риск): не форматировать существующий код одним махом; полный прогон `prettier --write` и правило `prettier/prettier` оставлены выключенными до отдельного решения владельца о едином стиле. `npm run format` и `lint-staged` (см. ниже) работают уже сейчас — просто не запускались по всему дереву разом.
- Husky + lint-staged: `npm run prepare` ставит хук `.husky/pre-commit` → `npx lint-staged`; `lint-staged` в `package.json` гоняет `eslint --fix` + `prettier --write` по staged `*.{js,jsx}` и `prettier --write` по staged `*.{json,css,md}` — форматирование staged-файлов на каждый коммит, без разового форматирования всего дерева.
- Точечно исправлен один настоящий неиспользуемый параметр: `SubscriptionManager({ user, ... })` → `{ user: _user, ... }` (аргумент нигде не читается). Три похожих предупреждения `no-unused-vars` (`Icon` в `QuickAdd.jsx`, `Art` в `ArchetypeShowcase.jsx`, `PersonaArt` в `JournalStart.jsx`) — не тронуты: это ложные срабатывания `no-unused-vars` для параметров, используемых только как имя JSX-компонента (`<Icon .../>`), без `eslint-plugin-react` ESLint не видит эту связь; проект сознательно не устанавливает `eslint-plugin-react` (не входит в согласованный список зависимостей), поэтому предупреждение остаётся и это ожидаемо.
- `npx eslint .` — 0 ошибок, 34 предупреждения (совпадает с базовым уровнем до изменений: `react-hooks/*`, `no-empty`, `no-unused-vars` — все уже существовавшие). `npm run build` проходит.
