# Передача Semantic UI Mentalix в Claude / Claude Code

Этот файл можно целиком отправить Claude. Он объясняет, что именно утверждено, где находится реализация и что нельзя менять при дальнейшей работе.

## 1. Что утверждено

Для Mentalix утверждён единый язык смысловой геометрии:

- почти чёрный фон;
- шрифт Onest;
- тонкие белые и серые линии;
- одна редкая золотая смысловая точка;
- дуги, линзы, маршруты, узлы и линии;
- никакого визуального шума, декоративных звёзд, случайных частиц и неона;
- движение показывает действие функции, а не просто украшает карточку.

Основные референсы находятся в UI Lab `?ui_lab=1`, варианты `20–24`.

## 2. Главная архитектурная договорённость

`src/components/SemanticGlyph.jsx` — единственный источник SVG-геометрии.

`src/components/SemanticGlyph.css` — единственный источник её смыслового движения.

UI Lab и реальные экраны обязаны импортировать этот компонент. Копировать SVG из него в лабораторию, экран или новый компонент запрещено: иначе референс и приложение снова разойдутся.

Инвариант:

> Если геометрия изменена в `SemanticGlyph`, она одновременно меняется в лаборатории и в приложении.

## 3. Документы — source of truth

Читать в таком порядке:

1. `DESIGN_SYSTEM.md` — токены, типографика, поверхности, радиусы и общие правила Mentalix.
2. `MENTALIX_SEMANTIC_MOTION.md` — перевод смысла в форму и движение.
3. `CLAUDE_UI_HANDOFF.md` — карта существующей реализации и порядок проверки.

Не заменять эти решения собственным новым визуальным направлением.

## 4. Где компонент уже подключён

### Практики

- `src/components/practice-art/RitualsArt.jsx` → `ritual`;
- `AskesisArt.jsx` → `asceza`;
- `NeuroArt.jsx` → `neuro`;
- `BreathingArt.jsx` → `breath`;
- `FocusArt.jsx` → `focus`;
- `MeditationArt.jsx` → `meditation`.

Эти обёртки оставлены ради стабильных импортов существующего экрана `Practices.jsx`, но больше не содержат собственных SVG.

### Личные ритуалы

`src/screens/Rituals.jsx` использует:

```jsx
<SemanticGlyph kind={semanticKindForRitual(ritual.name)} />
```

Смысловые варианты:

- молитва → `prayer`;
- холодный душ → `shower`;
- зачем ты проснулся / смысл дня → `purpose`;
- вода → `water`;
- всё остальное → `ritual`.

### Аскезы

`src/screens/Ascezas.jsx` использует:

```jsx
<SemanticGlyph kind={semanticKindForAsceza(asceza)} />
```

Смысловые варианты:

- отказ от алкоголя → `alcohol`;
- отказ от курения → `smoking` с буквальной сигаретой;
- остальные → `asceza`.

### Наставник

`src/screens/mentalix/art/PersonaArt.jsx` переводит роль через `semanticKindForPersona`:

- `kompas` → `mentor`;
- `mayak` → `companion`;
- `dnevnik` → `pathfinder`.

### Статьи

`src/components/ArticleCover.jsx` выбирает рисунок через `semanticKindForArticle(article)`:

- тревога, стресс, паника, страх → `anxiety`;
- сон, бессонница, ночь, восстановление → `sleep`;
- нейронные темы → `neuro`;
- внимание и концентрация → `focus`;
- дыхание → `breath`;
- неизвестная новая тема → `template`.

## 5. Как обеспечено совпадение с референсами

UI Lab `src/components/ui-lab/UiExperiments.jsx` больше не хранит отдельные SVG для вариантов `20–24`.

Она вызывает тот же `SemanticGlyph`:

- `20` — личные ритуалы;
- `21` — алкоголь и курение;
- `22` — нейротренажёр, дыхание, фокус, медитация;
- `23` — Наставник, Собеседник, Следопыт;
- `24` — тревога, сон, будущая тема.

В лаборатории:

- `animated={selected}` — движется только выбранная карточка;
- `highlighted={selected}` — золотая точка появляется только у выбранной карточки.

В приложении значения по умолчанию включены, поэтому тот же объект является активной смысловой иллюстрацией карточки.

Размеры и текстовая оболочка разных экранов могут отличаться, но SVG-геометрия и motion-код физически одни и те же.

## 6. Что Claude Code должен сделать

Если перечисленные изменения уже находятся в рабочей ветке, Claude Code не должен переписывать их. Его задача:

1. Прочитать три документа из раздела 3.
2. Убедиться, что UI Lab `20–24` импортирует `SemanticGlyph`, а не содержит дубликаты SVG.
3. Убедиться, что реальные карточки подключены согласно разделу 4.
4. Проверить отсутствие декоративных звёзд на затронутых карточках.
5. Проверить `prefers-reduced-motion`.
6. Проверить мобильную ширину, Telegram safe area и отсутствие горизонтального переполнения.
7. Пройти реальные экраны с авторизованными данными: Практики, Ритуалы, Аскезы, Наставник и Статьи.
8. Исправлять только обнаруженные дефекты интеграции. Не менять backend, API, тексты пользователя и бизнес-логику.
9. Перед коммитом показать список изменённых файлов и результаты проверок.

## 8. Критерии приёмки

- В лаборатории и приложении один и тот же SVG-компонент.
- В коде нет второй копии SVG вариантов `20–24`.
- Выбранная карточка лаборатории одна: только у неё золотая точка и движение.
- Реальные карточки сохраняют существующие размеры, тексты и действия.
- Рисунок не обрезан на мобильной ширине.
- На экране нет горизонтального скролла.
- При `prefers-reduced-motion: reduce` пространственное движение выключено.
- Backend и API не изменены.
- Claude показывает diff и просит разрешение перед commit/push.

## 9. Что не нужно делать

- Не переносить весь интерфейс на новый UI-kit.
- Не устанавливать Rive, Lottie или тяжёлую animation-зависимость.
- Не заменять SVG растровыми картинками.
- Не добавлять новый цвет.
- Не делать все линии золотыми.
- Не запускать несколько несвязанных движений одновременно.
- Не удалять UI Lab: она остаётся визуальным контрактом и местом сравнения.
