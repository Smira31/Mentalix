# Mentalix — QA guide

Статус: воспроизводимая инструкция для проверки текущего приложения.
Документ не является отчётом о прохождении тестов. Сценарий считается
работающим только после фактической проверки в указанной среде.

## 1. Среды проверки

Результат фиксировать отдельно для каждой применимой среды:

| Среда | Минимальная конфигурация | Что особенно проверить |
|---|---|---|
| Web browser | актуальный Chrome или совместимый браузер | web auth, console, навигация, API errors |
| Telegram Mini App | production или согласованный preview внутри Telegram | auth, fullscreen, haptics, safe areas, возврат |
| iPhone / mobile viewport | реальный iPhone предпочтителен; browser viewport — только предварительная проверка | клавиатура, fixed UI, scroll, верхняя и нижняя safe area |

Для каждого прогона записать дату, URL/build, устройство, ОС, Telegram/browser
version, тестовый аккаунт без персональных данных и результат.

## 2. Smoke test

- [ ] Приложение открывается без пустого экрана и бесконечной загрузки.
- [ ] В console нет критических ошибок, блокирующих сценарий.
- [ ] Доступны вкладки: Сегодня, Практики, Наставник, Библиотека, Тренды.
- [ ] Переход между вкладками и возврат работают.
- [ ] После повторного открытия сохраняется ожидаемое состояние авторизации.
- [ ] В Telegram верхняя и нижняя safe areas не перекрывают контент,
      навигацию и интерактивные элементы.

Предупреждение считается критическим, если из-за него теряются данные,
не открывается экран, не выполняется основное действие или приложение
становится непригодным для продолжения.

## 3. Today и core loop

### 3.1. Загрузка Today

**Given:** пользователь авторизован и открывает приложение.
**When:** загружается вкладка «Сегодня».
**Then:** загрузка завершается; hero и доступные блоки соответствуют данным;
нет критической ошибки или бесконечного loading.

### 3.2. Rituals

**Given:** у пользователя есть незавершённый ритуал.
**When:** пользователь открывает его из next action или Практик и отмечает
доступный уровень выполнения.
**Then:** результат сохраняется, Today обновляется, а повторное открытие
показывает сохранённое состояние.

Отдельно проверить empty-state без ритуалов и создание первого ритуала, если
этот сценарий доступен в используемом backend.

### 3.3. Askesis

**Given:** у пользователя есть неотмеченная аскеза.
**When:** пользователь отмечает удержание или срыв и, где применимо, указывает
причину срыва.
**Then:** статус сохраняется, Today обновляется, а введённая причина не
теряется после повторного открытия.

### 3.4. Next action

**Given:** у пользователя есть незавершённые ритуалы или аскезы.
**When:** открывается Today и пользователь нажимает главный CTA.
**Then:** показано одно релевантное следующее действие и открывается
соответствующий сценарий.

Дополнительно проверить состояния: нет практик, осталась одна практика,
все практики завершены.

### 3.5. Check-in

**Given:** check-in за текущий день ещё не выполнен.
**When:** пользователь проходит доступные шаги, выбирает состояние и эмоцию
либо использует разрешённый пропуск.
**Then:** check-in сохраняется, Today показывает завершённое состояние, а
данные доступны после повторного открытия.

### 3.6. Вечерний review

**Given:** текущее локальное время не раньше сохранённого `review_hour`, а
вечерний review ещё не завершён.
**When:** пользователь открывает Today и запускает «Анализ дня».
**Then:** открывается вечерний сценарий; ответы сохраняются; завершённый review
не предлагается повторно как незавершённый.

Проверить отдельно время до и после `review_hour`. Не подменять проверку
изменением `FORCE_EVENING_REVIEW`: production-код должен оставаться `false`.

### 3.7. Завершённое состояние дня

**Given:** все доступные практики и вечерний review завершены.
**When:** пользователь возвращается на Today.
**Then:** экран показывает завершённое состояние без ложного next action и
предлагает только допустимое продолжение.

### 3.8. Path / History

**Given:** у пользователя есть накопленные данные.
**When:** пользователь открывает Path, затем History и возвращается назад.
**Then:** отображается доступный прогресс и история; навигация не теряет
состояние Today; отсутствие данных обрабатывается как empty-state.

### 3.9. Theme

**Given:** backend вернул доступную тему недели.
**When:** пользователь открывает тему, выбирает доступный день и сохраняет
рефлексию.
**Then:** прогресс обновляется и сохраняется после повторного открытия.

Если backend не возвращает темы, отметить сценарий как `blocked`, а не
подменять его тестовыми предположениями.

### 3.10. QuickAdd

**Given:** пользователь находится на Today.
**When:** он открывает QuickAdd и выбирает каждое доступное действие.
**Then:** overlay открывается и закрывается без блокировки scroll; каждое
действие ведёт в правильный сценарий; возврат восстанавливает Today.

## 4. AI

Выполнить одинаковую матрицу для трёх персон:

- Собеседник (`mayak`);
- Наставник (`kompas`);
- Следопыт (`dnevnik`).

### Сценарий персоны

**Given:** пользователь открыл вкладку «Наставник» и видит выбор персон.
**When:** пользователь выбирает проверяемую персону.
**Then:** открывается её journal/conversation с правильным именем, текстами и
состоянием; нижняя основная навигация скрыта.

**Given:** conversation открыт и backend AI доступен.
**When:** пользователь вводит сообщение и отправляет его.
**Then:** сообщение появляется один раз; loading/typing-состояние понятно;
ответ либо корректная error-state появляются без потери введённого текста.

**Given:** в conversation достаточно сообщений для прокрутки.
**When:** пользователь прокручивает историю, возвращается вниз и отправляет
новое сообщение.
**Then:** scroll управляемый, история не прыгает, последний ответ доступен,
composer не перекрывает текст.

**Given:** conversation открыт на iPhone.
**When:** пользователь фокусирует composer, вводит многострочный или длинный
текст и закрывает клавиатуру.
**Then:** composer остаётся видимым над клавиатурой и нижней safe area;
layout не зависает и не оставляет недоступную область.

**Given:** пользователь находится внутри персоны.
**When:** он возвращается к выбору персон, затем в основное приложение.
**Then:** состояние возврата корректно; нижняя навигация появляется только
после выхода из конкретной персоны.

Для Следопыта отдельно проверить journal start и передачу контекста дня, если
backend и тестовые данные позволяют это сделать.

## 5. Practices

Для каждой видимой карточки проверить:

- [ ] Ритуалы;
- [ ] Аскезы;
- [ ] Нейротренажёр;
- [ ] Дыхание;
- [ ] Фокус;
- [ ] Медитации.

**Given:** открыт хаб «Практики».
**When:** пользователь нажимает карточку доступной практики.
**Then:** открывается правильный экран; back возвращает в хаб; карточка не
обещает завершённую функцию, если доступен только placeholder/empty-state.

Для интерактивных практик проверить старт, основной цикл, отмену/возврат,
успешное завершение и повторное открытие. Недоступную практику отметить
`blocked` или `not verified`.

## 6. Library

### 6.1. Статьи

**Given:** открыта Библиотека и выбрана вкладка «Статьи».
**When:** пользователь просматривает список, ищет статью, открывает материал и
возвращается назад.
**Then:** локальные статьи отображаются без дубликатов; поиск и reader
работают; empty-result понятен; внешняя ссылка, если есть, открывается ожидаемо.

Текущие статьи могут загружаться из frontend-данных. Не считать этим
проверенным backend-публикацию статей.

### 6.2. Курсы

**Given:** открыт раздел «Курсы», пользователь авторизован, backend доступен.
**When:** приложение запрашивает доступные курсы и пользователь выполняет
доступное действие.
**Then:** loading завершается; данные backend отображаются; success/error/empty
состояния различимы; повторное открытие не теряет подтверждённый результат.

Проверка курсов, статусов, заметок, доступа и оплаты требует работающего
backend и подходящего тестового аккаунта. Этот документ не определяет и не
расширяет backend-контракты. При отсутствии backend результат — `blocked`.

## 7. Состояния

Для каждого затронутого сценария, где состояние возможно, проверить:

| Состояние | Ожидаемая проверка |
|---|---|
| Loading | есть понятная обратная связь; интерфейс не зависает бесконечно |
| Empty | объяснено отсутствие данных и доступно следующее действие |
| Error | ошибка не ломает навигацию; возможен retry или безопасный возврат |
| Success | результат виден, сохраняется и корректен после повторного открытия |

Не симулировать backend-успех утверждением по коду. Если состояние нельзя
воспроизвести безопасно, зафиксировать `not verified` или `blocked`.

## 8. Проверки после редизайна 30.07.2026

Эти сценарии добавлены вместе с изменениями от 30.07.2026 и на устройстве
пока не подтверждены.

### 8.1. Fullscreen-поверхности

Касается `CheckIn`, `ThemeScreen`, `Onboarding`.

- Экран занимает весь экран: шапка Today и аватар не видны.
- Собственные кнопки экрана — «назад», «закрыть» — находятся ниже контролов
  Telegram и нажимаются. Проверять именно нажатие, а не вид: под контролами
  кнопка выглядит на месте, но тап забирает Telegram.
- Между контролами Telegram и первым содержимым нет двойного отступа.
- При открытой клавиатуре нижние кнопки достижимы, содержимое скроллится,
  страница под поверхностью не двигается.
- Проверять оба входа в «Тему недели»: из Today и из Библиотеки.

### 8.2. Клавиатура и зум

- Фокус в любое поле ввода не меняет масштаб страницы. Поля обязаны быть
  не мельче 16 px.
- Разведение пальцами увеличивает интерфейс: глобальная блокировка зума снята
  намеренно, её возвращение считается регрессией доступности.
- Быстрое двойное нажатие на кнопку срабатывает дважды.

### 8.3. Отступы и масштаб вкладок

- Все вкладки начинаются на одном расстоянии от контролов Telegram.
- Ширина контента одинаковая на Today, Практиках, Аналитике, Профиле,
  Библиотеке и в Настройках.
- Под нижней навигацией нет лишней пустоты: вертикальные отступы задаёт
  только `App.jsx`.

### 8.4. Today

- Приветствие соответствует времени суток и не содержит имени.
- Иллюстрация соответствует состоянию дня: нить — день не начат, лабиринт —
  день идёт или ждёт разбора, дверь — день закрыт.
- Quick Add не перекрывает нижнюю навигацию ни в развёрнутом, ни в свёрнутом
  её состоянии.

### 8.5. Аналитика

- При достаточных данных сверху стоит один вывод, ниже — остальные
  закономерности, ещё ниже цифры и графики.
- При малом количестве чек-инов экран честно сообщает, что данных мало,
  и не показывает выдуманных закономерностей.
- Формулировки описывают наблюдение, а не причину.

### 8.6. Профиль

- Лента вех содержит только подтверждаемые события.
- У нового пользователя вместо ленты — объяснение, что путь начнётся
  с первого чек-ина.
- Срывы отображаются наравне с достижениями.

### 8.7. Библиотека

- Каждая статья имеет обложку, статьи с разными темами получают разные
  архетипы, одна и та же статья всегда одну и ту же обложку.
- Вкладка «Практикумы» видна, помечена как «скоро» и не открывается.

### 8.8. Выбор собеседника

- Карточка листается одним движением и встаёт по центру.
- Свайп в конце ленты не закрывает Mini App.
- Индикатор снизу соответствует видимой карточке.
- Вертикальный скролл страницы при этом продолжает работать.

### 8.9. Практики

- Ритуалы и Аскезы открываются.
- Нейротренажёр, Дыхание, Фокус и Медитации помечены «Скоро», приглушены
  и не открываются.

## 9. Regression checklist перед commit/PR

- [ ] Проверен `git diff`; неожиданных файлов и секретов нет.
- [ ] Выполнен `npm run build`.
- [ ] Пройден изменённый сценарий.
- [ ] Проверены применимые loading/empty/error/success.
- [ ] Проверены основные вкладки и возврат.
- [ ] UI проверен минимум на mobile viewport.
- [ ] Для mobile-sensitive UI проверены Telegram, safe areas и клавиатура.
- [ ] Если добавлена полноэкранная поверхность — она использует `useFullscreenSurface` и проверена по разделу 8.1.
- [ ] Если добавлено поле ввода — его размер не меньше 16 px.
- [ ] Проверены web и Telegram, если затронут platform layer.
- [ ] В console нет новых критических ошибок.
- [ ] Ограничения и непроверенные сценарии перечислены в PR.

## 10. Definition of Done для проверки

Каждый сценарий получает один статус:

- **verified** — фактически выполнен в указанной среде; записаны дата,
  build/URL, устройство и результат;
- **not verified** — проверка не выполнялась или была только частичной;
- **blocked** — проверку нельзя завершить из-за конкретной внешней зависимости,
  например недоступного backend, тестового аккаунта, Telegram или устройства.

QA-проверка завершена, когда обязательные сценарии имеют явный статус,
критические результаты воспроизводимы, а `not verified` и `blocked` не скрыты
за формулировкой «работает».
